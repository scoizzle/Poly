## 0. Frozen core

```text
Domain (facts + uses ids)
  → DomainSession (libraries = compilation units: analyzers + maps + artifact contributors)
  → session.Analyze  → bags on nodes, replacements
  → dirty → STOP
  → session.Lower → artifact set on the session (fail closed if empty when required)
       · Syntax operation module (privileged: meaning + Interpreter sim; no bags)
       · other library producer artifacts (host / HTTP / … — delivery; call/bind the module)
  → consumers bind the module; they do not fork analyze/lower
MCP: harness — not a product door
```

| Frozen | Implication |
|--------|-------------|
| Nodes are the symbolic primary | No product-path primitive IR; shipped meaning = complete Syntax tree |
| Analysis owns facts and rewrite | Bags on nodes; `SetNodeReplacement`; semantic consume needs `AnalysisResult` |
| Libraries extend the session | `uses` ids; compilation unit = library; unknown/duplicate ids fail closed |
| Post-analyze Lower → artifact set | Catalog on session; Syntax module privileged for meaning + sim; other artifacts ≠ second sim |
| Doors map the catalog | Opt-in hosts; no core `Main`; doors do not invent operations |
| Do not add consumer-specific lowering flags | No `UseThisReference` twins; no Lower-inside-analysis |

**Forbidden:** Effect/Domain walk as shipped meaning; emitter/ABI one-offs; MCP as customer API; treating scratch store / `Stay.Create` / Store job names as architecture; DEI/MCP walk as product proof (the module is).

Always-on summary: [`AGENTS.md`](../AGENTS.md) Frozen core · Agent target.

## 1. Purpose

Neurosymbolic platform: author structured domain → lower to symbolic AST → analyze → VM (canonical). Domain = library of legal operations (no required `Main`). Goal: shipped correct end-to-end behavior, not framework completeness.

**Current consumers:** lower → Interpreter (module dictionary, host `ModuleInstanceExecutor`) | `session.Emit` (C# module) + bag-gated host files. MCP: `poly_workspace` → `poly_define` → `poly_simulate` (`create`/`invoke`/`evaluate` steps).

**Emit gate:** `session.Emit` registers the `vm-analysis-report`, then refuses (throws the first VM error) when the interpretation analysis of the lowered module reports an error; the report and the catalog stay on the session. `DomainSession.AnalyzeModule` is the one spelling of that module analysis (Emit, the IDE compiler and the tests call it): it analyzes the module with `DomainResultTypeProvider` over the default registry, the same stack `ModuleInstanceExecutor` uses, and a module's own declarations still win over the provider. The `session.Lower` module no longer carries the result family: `DomainResult`, `DomainResult<T>` and `ConstraintFailureException` come from `Poly.Runtime` (R-03b), so `Poly.Types.cs` holds only enums and value types. The type-list header (`CSharpWriter.Write(typeDefs)`) is the `#nullable enable` directive, then the System group (`using System;`, `using System.Collections.Generic;`), a blank line, then the Poly group (`using Poly.DomainModeling.Runtime;`, `using Poly.Runtime;`), a blank line, then the body; each group appears only when one of its identifiers is used, and an empty body is `#nullable enable` alone. Printed C# therefore needs a `Poly.Runtime` reference for every domain that prints a result. **Namespace (E-03):** `session.Emit` prints each entity file and `Poly.Types.cs` as a `CompilationUnitNode` whose `Namespace` is `DomainSession.CSharpNamespace(domain)` (the domain name; a keyword, non-ASCII, empty-segment, `Poly` or `System` name is refused until E-10 escapes names), so a banner, the inferred usings (including the `Poly.Runtime` family) and a file-scoped namespace come from the writer with no text surgery; an empty `Poly.Types.cs` stays `#nullable enable` alone. The DbContext, host and generated-tests units take the same namespace, and `DomainSession.QualifyForHost` spells every domain type as `<ns>.<Type>` in global-scope host files (a bare `Program`, a type named like the domain, or a `Task` would bind to the entry point, the namespace or `System.Threading.Tasks.Task`). The type-list overload `Write(typeDefs)` stays the global-namespace legacy path (printing and tests) until a later slice flips it.

**Words (current bind, not frozen):** `Domain` = facts. Analysis publishes **bags**. Surfaces (`uses sqlite` / `uses http`) select implementations. Lowering **reads** bags; the operation tree has no bag types. Bind is caller-supplied. Detail: [`docs/decisions/2026-09-03-facts-concerns-bags-store-bind.md`](decisions/2026-09-03-facts-concerns-bags-store-bind.md).

| Hard line | Implication |
|-----------|-------------|
| Domain is a module, not a process | No `Main` / `Program.cs` in core |
| Shipped ⊆ lowerable | Gaps stay in GitHub issues, not the parser/guide |
| Always-legal operations | Full tree per op; no `Comment` / `null` / host walk as meaning |
| AST is symbolic primary | No parallel primitive IR on product paths |
| VM executes Syntax programs | `Interpreter.Compile` fail-closed (an emit-time backstop: a conditional or coalesce whose arms mix an inline scalar and a heap handle is rejected, #605; analysis owns the conversion, T-09, so a tree that analysed clean never reaches it); no domain opcodes; C# emit is a projection |
| Domain lowers to generic ops | StageTransition / invoke / create / unique / clocks → existing Syntax + Store jobs on the one module |
| Product doors are opt-in | `uses`; CLI seeds ids only |
| MCP is harness | Author / inspect / simulate with caller context — not customer API; `poly_inspect` is a client of `ElementPath` / `ElementPathResolver` (`Poly/DomainModeling/Queries/`), the typed grammar `poly_inspect` uses (`poly_check`'s `NormalizeSelect` and `VerificationSummary.SelectScope` stay until M-04/M-05) |
| Lowered module is **domain meaning** | Artifact set on session; Syntax module privileged; fix Lower when sim ≠ print |
| Extend in the pipeline | Lower / analyze / replace — not emitter/ABI patches |
| Analysis required for semantics | Fail closed without `AnalysisResult`; `LoweringContext` takes analysis and domain as required members |
| One coherent path | Compose existing mechanisms |
| Immutable domain boundary | `DomainEvolution`…`Apply` only |

TFM: `net10.0`, nullable on, zero external deps in core `Poly/`. Policy: [`docs/decisions/2026-08-15-domain-library-extensions-mcp-harness.md`](decisions/2026-08-15-domain-library-extensions-mcp-harness.md).

## 2. Separation of concerns

| Concern | Owns | Must not |
|---------|------|----------|
| **Ast** | `Node`, `NodeId`, fluent API | Execution, domain shapes, analysis |
| **Analysis** | Framework, metadata, **node replacement** | Execution, domain concepts, MCP |
| **Interpretation** | Semantic passes, `Interpreter`, `AbiEmitter`, VM | Domain concepts; ABI forks for one consumer |
| **Introspection** | Host-neutral type/member model (CLR = first provider) | Depending on Interpretation |
| **DomainModeling** | Immutable `Domain`, evolution, DE→AST per op; contracts via `bind`. `LoweringContext` requires analysis and domain. Lowering reads published facts for requiredness (a missing structure bag throws), the resolved binding endpoint (a missing fact refuses) and unique (the declared constraint); it never recomputes them | Domain opcodes; `Main`; growing `Comment` as meaning |
| **Grammar** | Pattern-table engine (`Poly/Grammar/`) — decode / match / print; `SourceText` is the source-position surface (`GetLineColumn`, span slicing, per-document interned names) with `SpanToken<TKind>` as the span-form token — no production consumer yet (G-12..G-16 migrate consumers). The DSL expression parser is an iterative driver (`DslExpressionParser`, an explicit frame stack) over `DslOperatorTable` rows (binary and prefix operators, precedence and associativity): the matcher recognizes one atom at a time (`expr-primary`, flat header patterns), `Matcher` has no recursion budget, and nesting depth is the counted limit `DslLimits.MaxExpressionDepth` (256, a positioned error). The non-live `expr` / `expr-*` pattern chain is a recognizer kept for tests until G-24; it states precedence a second time until G-24 removes or derives it | Product tables inside the engine — DSL tables live in `DomainModeling`, C# tables in `Interpretation`; parallel pattern engines |
| **DomainModeling (DSL)** | One closed `.poly`; session binds `uses` concepts | Dialects; per-library token kinds; `Domain.ResolveHost` |
| **MCP** | Interactive harness + scratch store | Product doors; second evaluator; inferred `Main` |
| **Validation** | **Deleted** — constraints live under DomainModeling | Reintroducing a dormant rule surface |

**Deps:** Interpretation → Ast + Introspection. DomainModeling → Ast for pure lowering. Introspection ↛ Interpretation. V2 `Poly/Data/Modeling` is gone. Placement: [`AGENTS.md`](../AGENTS.md) Ops.

### 3.1 Analysis + metadata

| Piece | Location |
|-------|----------|
| Framework | `Poly/Analysis/` — `AnalyzerBuilder`, `Analyzer`, `AnalysisContext`, `AnalysisResult` |
| Pass contract | `INodeAnalyzer` — post-order; registration order is the schedule |
| Facts | `IAnalysisMetadata` via `SetMetadata` / `GetMetadata<T>` |
| Semantic passes | `Poly/Interpretation/Analysis/` |
| Entry | `Interpreter.Analyze` / `Interpreter.Compile` (Compile fail-closed on errors) |

Facts live on nodes. Semantic consumers fail closed without `AnalysisResult`. Domain authoring/MCP/compile analyze through `DomainSession.Analyze`, which binds that session before the pipeline. An unbound domain resolves ids through `ExtensionCatalog.Core` and throws when that catalog cannot load one. Catalog first (`DomainCatalogPass`); later passes read it. Subscriptions: `SubscriptionDispatchPlanMetadata` on stage + entity — store and C# export consume the **same** plan. Ownership: `OwnershipAggregateMetadata.OwnedEdges` / `OwnerEdgesOf` is the single owned-edge fact (`OwnershipAggregatePass.OwnedEdges` computes it once), `DMSTR010` is its diagnostic (two owner navigations to one type), and the single-owner Link op (L-13) and the executor cleanup (X-07) consume it. Quantifiers lower to `foreach` over collection nav (fail closed without store). Pass order: `Poly/Interpretation/Analysis/README.md`. Guide: `docs/interpretation/analysis-pass-guide.md`.

Session library selection: `LibrarySelection.Resolve` is the one place a document's `uses` ids are chosen against `SessionOptions.ImplicitIds`, and `LibrarySelection.Load` / `DomainSession.Create` load them. A document's non-empty `uses` list **replaces** the implicit set `[storage, persistence]`, so a `unique` property needs `persistence` or a vendor library (`sqlite`, `sqlserver`) in that list; a document with no `uses` gets the set, and a bare session (`SessionOptions.Bare`) loads none. `ConstraintCoveragePass` (C-05) is the one rule for the miss: a constraint whose loaded libraries install no `IConstraintCompiler` and whose `ConstraintCheckWriter.CoverageByConstraint` row is neither a writer kind nor a marker is `DMLIB001` in Analyze, positioned on the property or the type, and `ConstraintCompilation.Compile` refuses it in Lower; the writer table is the claim, so a new constraint record needs a row, a marker, or a compiler. `SessionOptions` carries the catalog, the implicit id set, the host target, the host's `StorageVendor` and the host-loaded `HostIds`, and lives on `DomainSession.Options`. `Resolve` appends `HostIds` after the selection, then the vendor replaces a listed `persistence` in place (or is appended when no storage compiler is listed, read from `ExtensionCatalog.ProvidersOf`), so a Db-mode document that lists a vendor never loads a second one. `PolyCompiler(ExtensionCatalog, SessionOptions)` and `DslCompiler` both select through it: there are no `CompileHooks`, no `PolyCompiler(string)`, no `ForDocument`/`ForAuthoring*` factories and no facade rule of its own, and the `Authoring` facet pack is a compile fact `PolyCompiler` sets, never a seed (the CLI word `--seed authoring` is an alias for the implicit set). A `WithDomain` reload resolves the new `uses` against the session's own catalog (explicit ids, no implicit-set substitution) and keeps the authoring facet pack and the target. That holds for a session built through `LibrarySelection`; a hand-built `SessionBuilder…Build()` session reports `Options.Catalog == Core` and reloads against Core (there is no production builder session). `ExtensionCatalog.KnownIds` reads the catalog keys and never probes. `Info` / `KnownTargets` / `ProvidersOf` read each library's cached `Register` probe on a throwaway builder (no core loaded): one probe per library per catalog instance, and a catalog from `With` re-probes. A probe exception propagates and the failure is cached; `ProvidersOf` re-runs each library's `Applies` on every call, so a throwing `Applies` propagates too but is never cached. These are read-only facts, never an input to lowering; C-05 shipped their first consumer (`ConstraintCoveragePass`'s hint), and the unknown-extension hint and catalogue checks in C-06 and C-07 carry the rest. The DSL printer's `uses` rule is interim (until C stops recording implicit ids in `Domain.Extensions`): `DomainDslPrinter(session, implicitIds)` omits the `uses` block when the extension list, minus `temporal`, equals the implicit set in order and no seeded contract is pinned; `export_dsl` passes `ProductCatalog.ImplicitIds` and does not read `Options.ImplicitIds`, because `apply_dsl` replaces `Modeling` with a session seeded from the previous extensions.

One generated C# namespace per entity. `Poly/DomainModeling/Analysis/ReservedNames.cs` is the table of names the C# exporter generates on an entity (`Create`, `CurrentStage`, `EnsureUnique`, the automatic-transition guard, per-nav `Create{Name}`/`Attach{Name}`/member/field, the `{Entity}Stage` enum, and the module names `DomainResult`/`ConstraintFailureException`/`Poly`/`System`) and, in a separate enum-scope table, the one name C# reserves on every enum's member list (`value__`, CS0076); `NameScopes.cs` is the entity member scope with the identity the emitter gives each member and the enum member scope (DMSTR001 for a repeated enum member, DMSTR009 for `value__`). `StructuralDomainAnalyzer` reports what the per-list duplicate rules do not: DMSTR001 for a name two lists declare (action↔policy stays with `ReportPolicyNameClashes`), DMSTR008 for two names that derive one generated member or constructor-parameter identifier, DMSTR009 for a reserved or own name, and DMSTR004 for a user type that reuses a generated type or namespace. Entity members and module names are two scopes with two rules; the enum scope is a third, one rule, checked against one enum's member list: `value__` (CS0076) and nothing else — an enum member may carry the enum's own name, because it is a value, not a nested member. **Module** rows (`GeneratedType`, `Namespace`) are checked against user type names: `DomainResult`, `ConstraintFailureException`, `Poly` (the `Poly.Runtime` import the printed C# carries) and `System`. **Member** rows are checked against one entity's members: `Language` (CS0542), `GeneratedMember` (an emitted member), and `GeneratedReference` — a type the generated class calls by its simple *expression*-position name, which a member of that name shadows. The round-2 probes (`NameScopeTests`) fix each row: `{Entity}Stage` collides whenever the stage enum is generated, because every constructor body prints `this.CurrentStage = AStage.<Initial>` (CS1061) — `<Initial>` is the stage the entity's `initial(Stage)` header clause designates, else the first declared stage (`EntityStages.InitialStage`; a designation naming no stage is DMINI001 and falls back) — the type position `AStage CurrentStage` alone would compile, and `HasStages` (stages exist and the single stage is not implicit) is exact for the body; `DomainResult` collides only when a body calls the non-generic form, i.e. an entity (or stage) action with no result members, or a `unique` property's `EnsureUnique` (CS1061) — a typed action prints only `DomainResult<T>`, which binds beside the member; `System` collides in expression position (`System.Convert.ToInt64(0)` for a folded zero divisor, `System.Text.RegularExpressions.Regex.IsMatch` for a pattern check — CS1061/CS0120) and the row is deliberately unconditional, because `new System.X(...)` in type position compiles and enumerating the writer's expression-position sites would twin its decisions, so a `System` member is rejected even in shapes that would build. `ConstraintFailureException` keeps no member row: probed, it compiles beside a void action's create-in and beside a stage-entry assign guard. `CurrentStage` is likewise gated on `HasStages`, so an implicit-single-stage entity leaves the name free. Per-nav rows cover the nav's own member, its `Create{Name}`/`Attach{Name}` factories and the collection backing field; they do not claim the nav's PascalCased member name is unavailable for every emitter path. C# keywords are never rejected here — escaping them is the printer's (E-10). Named gaps owned elsewhere: `ExistsWith{Property}` from the storage library's unique-create invariant (`Poly/DomainModeling/Libraries/Storage/UniqueConstraintCompiler.cs:43`), and the subscription-derived surface — `InitializeSubscriptions` (a real CS0111 today, probed), `When*` handlers, `Notify{Stage}Subscribers`, `Register…Subscriber` and the registry field — which S-05/L-14 owns.

Domain expression typing is the single acceptance gate for the domain layer: `ExpressionTypeAnalyzer` types through `ExprType` over the Introspection type/member model (`ITypeDefinitionProvider`); the coarse `TypeCategory` enum is gone (T-04). `Meaning/DomainTypeModel.cs` (internal; T-03) is that model: `Resolve` turns a domain name into an `ExprType` (an Introspection `ITypeDefinition` plus optionality; `ExprType.Unresolved` is never assignable), `Assign` answers `Identity`/`Widening`/`RoundingNarrowing`/`None` through the interface's `ResolveConversionFrom` (Implicit is `Widening`, Explicit is `RoundingNarrowing`; the policy stays here, the answers do not), and `KindOf` names the `NumericKind`; synthetic enum/class/struct definitions come from `DomainTypeDefinitionProvider`, which resolves primitives through `TypeMappingRegistry`. `ExpressionTypeAnalyzer` is its production caller since T-04 (see **The analyzer on the type model** below). `Meaning/OperatorTable.cs` maps syntax → `OperatorKind` (public, `Poly/Introspection/OperatorKind.cs`) only and fails closed on an undefined `ComparisonKind`; the operand typing and result resolution OQ-11 asks for landed in T-03b as an Introspection contract. **The platform answers conversions and operators (T-03b).** Two internal default-bodied members on `ITypeDefinition` (`Poly/Introspection/ITypeDefinition.cs`): `ResolveConversionFrom(source)` returns a `TypeConversion` (the kind, plus the declared method, or null when the platform applies the conversion itself) and `GetOperators(kind, other)` yields `DeclaredOperator(Signature, PlatformApplied)` for the definition beside the other operand (null: the same type). The consumer door is `GetOperator(kind, right)` (`TypeDefinitionOperatorExtensions`): candidates are the operators either operand declares beside the other; a candidate applies when each operand is identical to its parameter or converts to it implicitly; an all-identity candidate wins, otherwise exactly one applicable candidate is returned, and zero or two-plus is none (fail closed). Numeric promotion is the platform's answer for the pair (T-24): `UInt32 + Int32` is `Int64`, which neither operand owns, so `GetOperators` is pair-aware (a tie-break over per-operand sets could not rank `Byte + Byte` between `int` and `uint` without a C#-only rule in neutral code); `Decimal + Int64` is `decimal.op_Addition`, and `Float64 × Decimal` is none (neither converts implicitly to the other). Nothing else agrees today, and the ledger says so: the lowered-tree analysis types it `Decimal` (T-17, T-18) and the ABI executes it as `Decimal` (T-21); the domain DSL has no Float type, so the domain analyzer's column is n/a for it. The operand conversions the chosen operator needs are `parameter.ResolveConversionFrom(operand)`; those are what Lower must state as explicit conversion nodes. `GetCommonType(types)` returns the unique member the others identically or implicitly convert to, else none; it is derived, never stored. The .NET implementation lives under `Poly/Introspection/CommonLanguageRuntime/`: `ClrTypeDefinition` answers from reflection (`op_Implicit`/`op_Explicit`, static special-name `op_*`), then `ClrBuiltInRules`, the only source of the interface's built-in conversion and operator answers: the rule set answers every conversion and operator C# defines for built-in types (T-24): the implicit and explicit numeric conversions, conversion into `object` from any other CLR type, unary and binary numeric promotion through one `Promote` function, arithmetic, modulo, comparison, bitwise, shift, unary minus and plus, the Boolean operators, and string concatenation with any CLR operand; decimal's conversions and operators are the CLR's declared members. Deliberately none: enum, lifted, reference-equality, delegate and object operators. `PlatformApplied` is true for every operator of the simple types except decimal's, and for concatenation; string equality is the CLR's declared member, and a consumer must accept either form. To answer a conversion, four things still name .NET: `GetConversionFrom`'s CLR branch (`FindConversionFrom`), `IsAssignableFrom`'s `ClrTypeDefinition` branch, `IsNumericWideningFrom`'s `TypeCode` table, and the second conversion door (the internal `ResolveConversionFrom` beside the public `GetConversionFrom`); T-16 removes all four. `IsCollectionShape` and `GetElementType` also name CLR types in the Introspection root but do not answer a conversion. Modeled definitions answer from declared members: static `op_*` methods, which is Poly's modeled convention (the one `op_Implicit` already uses), not a platform fact; `DomainTypeDefinitionProvider` declares `op_Equality`/`op_Inequality` on enums and entities and leaves every other synthetic definition an empty shell. `And`/`Or` have no declared name and are intrinsic only. **Owner rulings (2026-11-12, #679):** the platform's conversion, promotion and operator rules sit behind an interface in `Poly/Introspection/` with the .NET implementation in `CommonLanguageRuntime/`, and everything else (the domain type model, the lowered-tree analysis, Lower, the VM) consumes the interface only. Language policy stays in `DomainTypeModel`; storage representation stays a VM fact. The long-term goal: the VM and Introspection are general enough to simulate almost any platform given the right foundational layers; .NET is the first platform, not the only one the design may assume. The contract is Introspection-internal today (`internal` members, neutral at signature level only: `ITypeMember.EmitRead` still returns an `Expression`); a platform in another assembly cannot implement it yet, and the members go public, a non-breaking change, in T-23 when the first non-CLR platform lands. **What the tree states vs what the ABI executes (R6):** the tree states operand types, the operator chosen and every conversion as explicit nodes whose meaning comes from this interface; the end state is that the ABI executes exactly what the tree states, or rejects it, and never decides meaning (owner row T-21). The contract carries no representation fact (`ConversionContract_ContainsNoRepresentationOrReflectionTypes`). The analyzer calls `GetOperator` only to state a `BinaryTyping` (T-04) and never to accept or reject; nothing uses `GetOperator` or `GetCommonType` as a gate until T-07. `Poly.Tests/DomainModeling/Analysis/OperatorOracleTests.cs` is the operator cross-check ledger: every operator cell over 22 operand definitions (8,800 cells) in three columns (the interface's answer with the operand conversions; the lowered-tree analysis's resolved type; what the VM executes, run with typed parameters and probe values that expose 32-bit wrap, 2^53+1, decimal exactness and integer truncation), four divergence kinds (`analyzer-disagrees`, `lowered-analysis-disagrees`, `abi-diverges-from-tree`, `abi-rejects-defined`), each owned by the row that removes it (T-06, T-07, T-10, T-17, T-18, T-21, T-22), except `Text + X` for a CLR `X`, which the platform defines and Poly's language policy rejects: a permanent T-07 rule; each divergence has exactly one owning rule and each rule pins its matched-cell count and a checksum of which cells it owns (never the values the VM computed), so an unowned divergence, a divergence two rules claim, a stale rule, growth and shrinkage all fail the test (a fixing slice edits the count or deletes the rule); The merged ledger totals are analyzer 261, lowered 2,163, VM 3,486. T-04 quotes it. Declared range bounds are exact at parse and in the assign guard: a `Number`/`Int`/`Int64` bound is a `long`, a `Decimal` or any other non-Number-family bound is a `decimal`, and neither is ever a `double`. Analysis-time bound arithmetic is exact (V-05b): `ValueRange(decimal? Min, decimal? Max)` (null endpoint = open) carries `Add`/`Sub`/`Mul`/`Join`/`TryMeet`/`Below`/`Above` through the immutable `IntervalTransfers` table, `ProvableTruth.Decide` answers a comparison over intervals as true/false/unknown, and `ConstraintMerge.TryCompare` orders mixed numeric bounds through `ExactNumber` exactly when representable, else master's double; `Poly/DomainModeling/Analysis/ExactNumber.cs` is the decimal-backed exact primitive (internal). `ConstraintMerge.TryCompare` keeps a `double` fallback only for a public API-built `new RangeConstraint(double, double)` bound. A derived bound beyond `long` is not wrap-modelled (#624, `KnownUnsound`). Rules, provenance and the per-slice interim state: [`decisions/2026-11-11-domain-type-model-and-numeric-rules.md`](decisions/2026-11-11-domain-type-model-and-numeric-rules.md). **The analyzer on the type model (T-04).** `ExpressionTypeAnalyzer` (core, `ExpressionTypeInference.cs`, `ExpressionTypeRules.cs`, `ExpressionTypeAnalyzer.Binary.cs` and the `Arms.*` partials) infers an `ExprType` per expression and accepts exactly what it accepted before: the move changed no verdict (`AnalyzerBehaviourPinTests` records every verdict from master; T-04 leaves the ledger's analyzer column at its 245 cells: 107, 96, 6, 6, 4, 8, 11, 7; T-24 adds 16 permanent A1 cells, `analyzer rejects, tree String` (T-07), for 261). The representation: a whole-number literal, `Count`, `Sum`, arithmetic results of `InferValueType` and Text + Text carry no domain name (`DomainName` null) over a family definition; a decimal literal carries `"Decimal"`; a declared or allowlisted name carries that name; `Compatible` applies the name rule only when both names are non-null. One derived key (`Family(ExprType)`, a pure function of the definition: numeric family = Int32, Int64, Float64, Decimal; date family = DateOnly and DateTime) serves `Compatible`, match-arm `Unifies` and the arithmetic arms; acceptance never calls `Assign` or `GetOperator`. Lenient (the old Unknown) is one predicate: no definition, or a definition that is neither primitive nor enum (entity, value type, Binary); a name with no definition (undeclared, lowercase `long`) is named-unresolved and lenient. A declared primitive is typed by its semantics, never by the temporal map, so a hand-built `Date` stays a date. **`DomainTypeModelMetadata`** is stamped on the `Domain` node at the top of the pass (the session's type maps) and built lazily from the type lookup's domain when a walk has a lookup but no stamp (one resolver); a walk with no Domain root has no lookup, so no model and no stamp, and names resolve through the legacy allowlist only. The analyzer's own name table (`ResolveName`, `LegacyClrType`, `ClrTypeOf`) sits beside the model's provider and disagrees with it for lowercase CLR spellings and under a pack override of a legacy name; T-05 removes it. Consumer contract: a reader runs after the `DomainExpressionType` pass (`CorePasses` order) and fails closed if the stamp is absent. **`TypedExpressionMetadata(Type, Binary)`** replaces the public `CatalogTypedExpressionMetadata` (a public-API removal); `Binary` is a `BinaryTyping(Result, Kind, IsIntegerDivision, MayOverflow, Checked)` stamped on `Add`, `Subtract`, `Multiply` and `Divide` over resolved numeric operands from `GetOperator`. Absent `Binary` means the analyzer did not state an operator: never "operator undefined" (acceptance does not read it; Float64 × Decimal is accepted and stamps nothing) and never "unknown type". A stamp whose `Binary` is set is never read back as a type by `InferType` or by `TemporalMeaning.TypeNameOf`; arithmetic stays Unknown to inference, as before. `Checked` is false until T-11. Visible changes: a Decimal is named `Decimal` in type-mismatch messages (#581; Float, Double and Int32 still read `Number`), and an integer-valued literal beyond `long` reports `Integer literal N is out of range for Number (64-bit)` rather than "Fractional" (#515; `5.0` and `1.5` stay fractional). Synthetic enum, entity and value type definitions are empty shells apart from the equality operators (T-03 carry). The lowercase CLR spellings (`long`, `decimal`) stay lenient in the domain, as before; T-05 decides. Temporary seams and their removing rows: the legacy name allowlist, the named-unresolved type and the typeless-name leniency (T-05); `ExprType.NullLiteral` (T-06); the stamp without a gate and absent-`Binary` (T-07); `Family`, `Compatible` and the arithmetic arms over it (T-05 to T-07, T-10). V-02 has not landed: it reads `DomainTypeModelMetadata` and keeps no private model.

### 3.2 Node replacement

**The** rewrite mechanism: `context.SetNodeReplacement` / `GetNodeReplacement` (`Poly/Analysis/`). Passes do not mutate the tree; backends compile the replacement. Prefer an `INodeAnalyzer` over a product-local rewriter or emitter patch.

### 3.3 Direct AST → VM

| Piece | Location |
|-------|----------|
| Emitter | `Poly/Interpretation/Vm/Abi/AbiEmitter.cs` |
| Façade | `Poly/Interpretation/Interpreter.cs` |
| Runtime | `VmState`, `VmProgram`, … under `Poly/Interpretation/Vm/` |

No intermediate primitive IR. Keep the emitter a generic compiler of known nodes — fix upstream (lower / analyze / replace). Known members: `Ref` / `Ref<T>` (`Poly/Interpretation/Vm/Ref.cs`), not `typeof(T).GetMethod(...)`. `Await` executes by blocking on the operand. `Task` / `Task<T>` / `ValueTask` / `ValueTask<T>` run through `Ref`-bound helpers whose `GetResult` waits. Any other structurally awaitable type resolves `GetAwaiter`, `IsCompleted`, `OnCompleted` or `UnsafeOnCompleted`, and `GetResult` through the type provider, and blocks on the continuation when `IsCompleted` is false. Analysis types the result as `T` or void. An `IsAsync` AST method body yields a completed `Task<T>` (`Task.FromResult<T>`) or `Task` (`Task.CompletedTask`) at its return, so a caller's `Await` composes; a method that is not `IsAsync` is left alone. No state machine, no scheduler. The resume spine serves two bodies: `SuspendNode` in the compilation-unit body (a flat PC switch), and an iterator method body (`yield return` / `yield break`, `VmIterator<T>`), where resume is hierarchical. An outer switch on the region id in the iterator's private frame routes into a *region* (a block that owns yields; every block is a region, and a loop whose body is a bare statement has none of its own), and that region emits its own inner switch on a region-local step that selects the yield's resume label. Spill, reload and the resume label stay local to each yield. The iterator owns its slot array: `MoveNext` copies it onto the shared stack above the stack pointer, runs the step, and copies it back, so a nested call between two yields cannot overwrite its spills. A try/finally, `using` or `foreach` around a yield is lowered, not a CLR try (the CLR cannot resume into one): a frame flag marks the region entered, `Dispose` resumes the suspended body into a per-region dispose label that runs the outstanding cleanup once, `yield break` / `return` take the same label, and a handler around the iterator body runs every entered cleanup on an exception. A `break` / `continue` that leaves such a region and a `goto` inside one are rejected (IT0008, IT0009).

### 3.4 Domain lowering

| Piece | Location |
|-------|----------|
| Expressions | `DomainExpressionLoweringPass` (+ session `ExpressionMeaning` for libraries) |
| Effects | `EffectLoweringPass` — real nodes, not `null` |
| Module | `DomainProgramProjection.ToSyntax` — types + ops; no `Main` |
| Policy eval | `ModuleInstanceExecutor.EvaluatePolicy` → cached body → `Interpreter` |

Expand to **generic** Syntax (no domain opcodes). StageTransition / self-invoke / cross-entity / for-invoke / create / unique / clocks — shapes and residual debt: [`docs/interpretation/domain-execution-model.md`](interpretation/domain-execution-model.md). ADR: [`docs/decisions/2026-06-08-domain-lowering-boundary.md`](decisions/2026-06-08-domain-lowering-boundary.md). Named invoke runs module method bodies from `session.Lower` (same tree print uses). Do not add consumer-specific lowering flags or a second effect interpreter.

**Module cache beside `CompiledDomain` (#467 K5).** `RuntimeAnalysisCache` (`Poly/DomainModeling/Analysis/`) is a static `ConditionalWeakTable` keyed by `Domain` identity, holding six parts per domain: the bound session, the domain analysis, the lowered module trees (subscription and policy bodies included), and the catalog index. Lowering, the analysis passes, `ModuleInstanceExecutor`, MCP and the product pack read it before — or without — a session-owned `CompiledDomain`. `CompiledDomain` (`Poly/DomainModeling/Compile/`) is per `DomainSession` and uniquely owns VM analysis; its domain analysis and module are the cache's same references, not copies, and the VM analysis stays off the static cache (#359). Ruling 2026-11-10 (#467 K5) kept both: merging them would re-key about 45 production call sites (54 references in 25 files) and 94 test call sites to a session and reopen the #387 "which session owns a `Domain`" ruling.

**Contract contributions.** A library's `Register` may call `SessionBuilder.AddContract(surface, bodies, targets)` to contribute one `ImportedContract` surface, optionally the body factory per endpoint, and the host targets the package is for. The slot is attributed to the registering library id, one contributor per contract name, and frozen as `DomainSession.ContractContributions`. `uses <id>` seeds the surface onto the resolved domain as an `ImportedContract` (`UsesId`, and `Pin` when the source wrote `uses <id> <pin>`); the body binds it. The surface's `Version` is the package's, never the pin. A body is a `Func<Block>` called once per splice site (fresh node ids; a body reused across binds fails closed) and once per bind by boundary analysis (#425); it is never run at Load. Lower splices a contributed body at its bind: the bound parameter must be named `request` and the body reads it as the `Parameter("request")` node (no `Variable` alias), then the body's statements, then its final `return <DomainResult>;` as the call outcome behind the existing failure guard. An in-solution `InternalDomain` bind with no body is erased and the local action still runs; an `ExternalProvider` endpoint with no body fails Lower. No `{Contract}Adapters` type is emitted. **Platform target:** the target is a host fact (`DomainSession.Target`, set by the compile call, never by `uses` and never a `Domain` field). A contribution that declares targets (`ContractContribution.Targets`, e.g. `posix`) is `DMCON004` when the host target is absent or not among them; the declared set is implementation metadata, not surface, so it is not in the fingerprint.

**Binding facts and the surface pin (#420).** `ContractIntegrationAnalyzer` publishes `ContractSurfaceMetadata` on each contract (library, source, version, fingerprint, pin, pin kind, matched) and `ContractBindingMetadata` on each bind (same surface identity, authored endpoint, resolved endpoint, action, parameter, status). The pin is exact: a 64-lowercase-hex pin is compared to the surface `Fingerprint`, anything else to `Version`; a mismatch is `DMCON010` on the contract and Lower refuses. No pin is the in-workspace case: no error, and the bag carries the resolved fingerprint. A bind may name the original action: candidates are matched by `ContractEndpoint.SourceName`, a payload type must accept the bound parameter (identity, or a narrower same-property-shape value type by `ConstraintMerge` subsumption), and the unique most-constrained accepting payload wins (`DMCON011`, a warning naming it) while incomparable candidates are `DMCON012`. A missing endpoint is `DMCON013`. Every action of the bound name on its entity must share one parameter list (name and type); a stage variant with another signature is an error, not a first-wins `Bound`. Lower reads the resolved `ContractBindingMetadata.Endpoint`, so print and simulate splice the same identity; a missing binding fact refuses.

**Boundary constraints (#425, decision 21).** At a resolved bind, `ContractBoundaryCheck` publishes `ContractBoundaryMetadata` (precondition verdict, postcondition verdict, compatibility) beside the binding fact. The caller's argument must sit inside the endpoint's public payload property constraints: a proof is silence, a disjoint pair is `DMCON014` and Lower refuses, and a merge that cannot decide (`ConstraintMerge.MergeResult` `Unmergeable`, or a caller wider than the obligation) is `DMCON015` and does not block Lower — when the payload obligation is `range`, `length` or `equals`; for a `required`, `pattern` or `default` obligation with no same-kind caller constraint the bind stays on the generic `DMCON001` refusal, as on `origin/master`. **Scope rules.** A precondition is written against the source *entity*, so a bare `PropertyAccess` in an exported `require` is entity state and is never decided from the argument — only a `ParameterAccess` naming the bound parameter of a primitive payload is argument-scoped, and anything else is `DMCON015`, never `DMCON014`. `Empty` is a disjointness proof only for `range`, `length` and `equals`: a `pattern` or `default` mismatch the payload relation cannot satisfy returns no verdict, so the bind keeps the generic `DMCON001` refusal `origin/master` already gave it. A same-shape constraint mismatch is decided here instead of the generic incompatible error, so a wider caller is unknown rather than refused; a shape mismatch, and a source-name bind with several candidates none of which accepts, stay `Incompatible` — that asymmetry is deliberate and fail-closed, since widening the multi-candidate case would turn a refusal into a lowering. **Known limitation, fail-safe.** The decided precondition path matches on the caller's own local parameter name, because `ContractEndpoint` carries no parameter name: the same expression is `DMCON014` when the caller names its parameter `request` and a silent `Unknown` when it names it `amount`. It never invents a violation, and the DSL cannot author a parameter-scoped precondition today, so the path is reachable only from hand-built endpoints. Do not "fix" it into a violation — a producer that can emit a parameter-scoped precondition decides the naming first.

**The postcondition half walks the contributed body.** A body that writes a payload member outside a declared `range`, `length`, `pattern` or `equals`, or writes null into a required payload member (the DMEFF015-class presence invariant), is `DMCON014` and Lower refuses; the walk names the member and the constraint. Requiredness is implicit on a payload: a value-type member is required unless marked optional, and the DSL cannot mark one optional. A write whose value the walk cannot decide, a payload handed to a call that may mutate it, a method call on the payload, or an `if` whose branches leave a member at different values is `DMCON015` and does not block Lower. A write that provably stays inside every declared constraint proves that member only for the kinds it can evaluate (a constant written to a `unique` member, or a string `equals`, is `Unknown`, not proven). A body is `Proven` only when it ends in a `return`, has no undecided write and no escape; the final `return` expression and local-assignment right-hand sides are walked too. A body that does not end in a `return`, or whose factory throws, is `Unknown` with one `DMCON015`. A surface-only contribution has no body, so its postcondition half is `Unknown` silently. The note is not in the fingerprint, is not a pin input, and does not waive `DMCON010`.

**Constraint contributions.** A library may register an `IConstraintCompiler`; core places its AST at a semantic anchor (`ConstraintAnchor`), inserts contributed parameters before the method's first optional parameter, and threads them along the lowered call set. The storage libraries own `unique`: the guard calls the in-process `Poly.Runtime.IStoragePort` — `Exists` is the advisory pre-check (pending key or database), `TryReserve` is the atomic check-and-reserve in the port's own in-flight set, and `Record` stays a shim until L-11 flips the create guard. A reserve is local: a host whose authority is a persisted unique index may accept a duplicate that is already persisted and fail at commit, and `Exists` never owns the store's verdict. Every key goes through `Poly.Runtime.KeyCodec.Canonical`, so the simulator and the printed host cannot drift. The port is read-only — no writes and no `SaveChanges` — and is implemented by the generated `{Domain}DbContext` (`TryReserve` adds the pending key; the unique index stays the authority) and by the interpreter host's session port, which delegates its key set to the thread-safe reference `InMemoryStoragePort` and is atomic under its own lock. The module never names a host context type, and there is no second persistence runtime. Contributions follow declaration order (Q12): `ConstraintCompilation` walks entities in `Domain.Types` order and properties through `EntityDeclarationOrder.Properties`, and `ContributedMethods.Install` keeps only the stable `LibraryId` sort. The one deliberate name order is the threaded parameter slots (`ContributedMethods.cs:276`, by `LibraryId` then parameter name).

**Stage ledger and constraint coverage.** `SessionBuilder` records one `StageContribution` per library and pipeline stage it enters: Load in `Register`, Analyze when the registering library adds an analyzer, Lower when it adds a constraint compiler. `DomainSession.Analyze`, `Lower`, `Emit` and the internal `Compile` refuse a session whose core library is not loaded at Load. Registration attributes an analyzer or compiler to the library whose `Register` is running; a registration made outside a library load records no stage row. Constraint check coverage is `ConstraintCheckWriter.CoverageByConstraint`: each `Constraint` record names the writer kinds it can emit or the owner that writes its guard (or, with a `marker:` prefix, why no guard exists; `unique` is storage-owned), and `BuiltinConstraintCompiler` claims exactly the rows with kinds. A `pattern(...)` regex is evaluated in one place, `PatternSemantics` (`Ontology/Constraints/`): `EndAnchored` reads an unescaped trailing `$` as absolute end of input (`\z`), so analysis, the constant-assign fold, the printed guard and the contract boundary check share that one meaning while the model keeps the authored pattern for export. Same-type constraints combine through `ConstraintMerge.MergeResult` (`Net | Unmergeable | Empty`): `Empty` is the only unsatisfiable verdict, an unregistered kind is `Unmergeable`, and identical `unique`/`default` are idempotent; `Merge` is the net-or-null convenience for callers that do not need the difference. `AddConstraintToPropertyChange` treats an identical constraint as a no-op, so a duplicate never reaches Lower as a second guard.

**Diagnostic allowance.** There is no contradiction gate over flow diagnostics. A reader-found copy is an `ObservedFlow` (`SessionBuilder.WithObservedFlows`, frozen on `DomainSession.ObservedFlows`) checked by the existing assign checks: `EffectAnalyzer` calls `IsConstraintSubsumed` for a `length` pair and `WriteVerification.DecideRange` for a `range` pair (`DMEFF008` on the target property) and reports an optional source flowing into a required target (`DMEFF014`, #439), and `ExpressionTypeAnalyzer` calls `CheckCompatible` (`DMSEM003` on the target property); an unresolvable or self path is `DMSEM005` on the domain. Nothing is inserted into the tree. Unacknowledged flow diagnostics are errors and block through `ThrowIfHasErrors`, the gate over the severities analysis reports; `WarningPromotion.Apply` is not a second gate — it runs after the report and copies the list (below). A `DiagnosticAllowance` (`SessionBuilder.WithDiagnosticAllowances`, frozen on `DomainSession.DiagnosticAllowances`) names a diagnostic code and the finding's element path (`Domain/Entity/Property`) plus non-blank provenance ids; a match downgrades only a `DMEFF008` or `DMSEM003` flow diagnostic (or a contract finding, below) to a warning, which stays in the report and does not stop Lower. **`DMEFF014` is not acknowledgeable (#444):** `ProvableGuards` reports a copy of an optional property or optional parameter into a required property, on the assign, unless a provable guard clears it. The four guards are a dominating `if` presence check (an intervening assign that may null the source drops the fact), an action `require` whose policy proves presence, an entry policy (every transition into a non-initial stage is on an action whose policies prove presence, and no action that can run in the stage can re-null it), and a stage `require` (written in the stage header before `{`, like an action's; `Stage.Policies`, the invariant: an action that can null a property the stage proves present is `DMEFF015`; an entity-level action counts for every stage). Entry, exit and subscription bodies are never cleared, and a transition there is an unguarded entry. An observed flow has no action and no stage, so no guard site clears it. An allowance naming a reported `DMEFF014` is the `DMALW002` error and consumes nothing. An allowance no analysis arm consumed (wrong code or path, stale after the flow became compatible, blank provenance) is the `DMALW001` error. `WithDomain` copies both lists on both branches. ADR: [`docs/decisions/2026-11-08-diagnostic-allowance.md`](decisions/2026-11-08-diagnostic-allowance.md).

**Unverified writes (Q4).** Silence from a write check means verified — with one exception, below: non-`range` kinds on `assign` and initializer writes (V-08). Every write to a property carrying a `range` constraint — `assign`, entry/exit and `when` bodies, and `create`/`create in` initializers (evaluated in the creator's scope, with the creating action's parameters in scope, against declared ranges only: no `require` narrowing and no stage invariants, unlike an assign) — gets exactly one `WriteVerdict`: `Satisfied` is silent and counted, `Violated` is a `DMEFF008` error ("entirely outside"), and `Undecided` is a `DMEFF008` warning when the value has a known range ("can fall outside") or a `DMCS003` warning otherwise (no usable bound, an operator the interval flow does not model, or a constraint kind with no flow decision). `ConstraintKind.WriteRelevant` is the kind's own claim that a computed value can be decided; this slice sets it for `Range` only, so length/pattern/equality writes stay silent on an `assign` or an initializer, and an unregistered kind is fail-closed. A `length` pair **is** still decided on an observed flow and in the parameter arm, which compare declared bounds; the call chain (`ValidateCallChainPostconditions`) decides through the same `DecideRange` and records every non-`Satisfied` outcome through `WriteRecorder`, deduplicated per effect node (V-05b); a postcondition with no value range is still skipped silently. `WriteVerificationFacts` (`Analysis/WriteVerification.cs`) is the analysis-side record on the `Domain`: one entry per unverified write plus a `Verified` count, never one per constraint, and never "proven" while a write is unverified. `DMEFF008` itself is unchanged.

**The check verdict (V-04).** `VerificationSummaryExtensions.GetVerification(this AnalysisResult, Domain, string? path)` (`Analysis/VerificationSummary.cs`) derives the `CheckVerdict` on demand from those facts plus the final diagnostics — not a second `IAnalysisMetadata`, because an analyzer cannot see the final diagnostic list at publish time. The fold: any in-scope **error of any code**, or any proven violation, is `Violated` (so an error with no fact behind it — a non-`range` kind, V-08 — still counts, and no diagnostic-to-fact match can mask it); an unverified write is `Unknown`; nothing at all is `Proven`. `Violations` counts distinct nodes, fact-backed and unbacked alike. The rows are the write findings (`DMCS003`, and a `DMEFF008` warning) enriched from the fact with the same node **and** the same reported code, de-duplicated by (node, code), and a recorded fact with no finding is synthesised into a row, so `Unknown` always has at least one row; a `DMCS003` row need not be a write finding (`ConstraintQualityAnalyzer` reports that code too) and then carries no property, constraint or reason. `VerifiedWrites` is whole-domain only, because `Verified` is a count with no node. `path` is the MCP select form — `Entity` or `Entity.Member`, dot or slash, an optional domain prefix, and a stage action without its stage segment — checked against the domain tree, so an entity with no writes is a valid scope and reads `Proven`, a path naming nothing is `Unknown` with no rows, and a node that does not resolve is in every scope. A call-chain finding is attributed to the **callee** element that assigns — the chain is named in its message — so a caller-scoped read can say `Proven` while the whole domain says `Violated`. A missing facts bucket is `Unknown`, never an empty `Proven`. An observed flow goes through the same recorder: an unconstrained source is a `DMCS003` warning naming the flow plus an `UnknownBound` fact, a `range` pair is decided by `WriteVerification.DecideRange`, a source inside the target is counted verified, and a wider source keeps its `DMEFF008` with a `PossibleViolation` fact beside it. `WarningPromotion.Apply(diagnostics, codes)` is the warn-as-error primitive: it promotes reported warnings of the listed codes (`null` = every warning) after the report and copies the list, so an allowance-downgraded finding of a promoted code is promoted back and the analysis keeps the severities it reported; inert until C-11, and `polyc --warn-as-error` is unchanged.

**Contract tolerance (#422).** The same acknowledgement covers the decision-8 contract findings: `DMCON002` (unclosed public signature), `DMCON003` (public action on an internal entity), `DMCON004` (platform target), `DMCON005` (bind names an unregistered contract), `DMCON010` (pin mismatch), and `DMCON013` (endpoint not on the surface). A match reports the finding as a warning on the same record and stores one `ContractToleranceMetadata` fact per (code, element path) on the domain. Lower, Emit, Compile, and direct projection then refuse through `ContractToleranceGate`, naming the fact; a non-`Bound` `ContractBindingMetadata.Status` also refuses in the splice. This is not the deleted #430 flow gate: the fact exists only when an acknowledged contract finding was recorded, it covers contract findings only, and it never re-derives severity from a rules table. A tolerated flow finding still lowers. `DMCON012`, the package-metadata `DMCON001` errors, and flow codes are not acknowledgeable through this arm. `InternalDomainProducer` takes no analysis and is not a gate.

**Visibility to C# access (L-22, #604).** `Poly/DomainModeling/Lowering/DomainAccess.cs` is the one rule: an entity, value type or action prints `public` iff marked `public`, else `internal` (Q13); enums stay public and a stage enum follows its entity. `Demote` makes a member of a public type `internal` when its signature names an internal type; `NavigationAccess` applies it to a navigation (L-22b): a public owner's navigation to an internal entity prints `internal`, every other owner's stays `public`. `ForInfrastructure` is the host clamp (the DbContext is internal when any entity is internal; a DTO is internal when its entity or any domain type it names is) and is L-22's minimal seam: P-17 owns the final host shape. The pack emits an explicit EF `HasMany`/`HasOne` mapping (`DbContextGenerator.BuildExplicitNavigationMapping`) for exactly those navigations, because EF discovers only public ones; its inverse is `StorageNavigation.InversePropertyName`, resolved once in `StorageAnalyzer`. `DMCON019` (`ContractIntegrationAnalyzer.ValidatePublicEntityInternalTargets`) covers a public entity's entity-typed property (persistence ignores it, so demoting it would lose data) and a many-to-many navigation to an internal entity (fails closed until L-22d). `ValidatePublicStageGroups` closes a public stage group whose other copy returns an internal entity (`DMCON002`).

**Failure-construction seam.** `Poly/DomainModeling/Lowering/FailureLowering.cs` is the only AST-facing constructor of a typed failure: `Call(spec)` is `Poly.Runtime.DomainFailure.<Kind>(message[, path[, guard]])`, `Return` wraps it in `return DomainResult[<T>].Failure(…)`, `Propagate(type, child, callerPath)` is `return type.Failure(child.Error![.At(callerPath)])` (kind, message and guard survive the rewrap), and `Throw` / `ThrowFrom` are the void-body forms (`throw new ConstraintFailureException(…)`, text only, L-04 deletes them). Lowering never prints `Failure("…")` or `ErrorMessage ?? ""` in a returning body. **Path rule:** a leaf failure's `ElementPath` is `Entity.Member` (`Entity.Action` for a stage or policy refusal, `Entity` alone for `EnsureUnique` without the port); only a failure rewrapped from a callee (create-in, invoke, `for` fan-out, contract adapter) gains the caller prefix `Caller.Action` through `At`, so a nested range failure reads `Product.Hold.Reservation.Qty`. A `when` handler and its `Notify{Stage}Subscribers` dispatcher return `DomainResult` (L-03h), so a failed nested result is returned at once across the handler too: the handler passes a failed `invoke` through with no prefix (it is fan-out, not a caller), the dispatcher returns the first failure and runs no later handler, and the transition or `Create{Nav}` that fired the notification returns it to its own action with its own prefix. A handler still throws for its assign and create guards until L-04 (`LoweringContext.ReturnsDomainResult` is the interim seam: only the notify site reads it). The create-nav helper (`Create{Nav}`) and the entity's own `EnsureUnique` guard are not callees and pass through with no prefix, which keeps a unique assign's path the same whether or not the storage library rewrites it. `Guard` is set only for `Policy` (the real policy name, never `not_P`) and `Stage` (the stage name). The receiver prints fully qualified (`Poly.Runtime.DomainFailure`), so a member, enum, value type or entity named `Poly` shadows it: `Poly` and `System` are reserved for every entity and as an action parameter name for every action, and `DomainResult` is reserved as an action parameter name for an action with no result members (void actions call `DomainResult.Success()` / `.Failure(…)` in expression position; a merged void/typed stage-dispatched copy is deliberately over-rejected). `ReservedNames.TryReservedAsActionParameter` reads each row's `AppliesToAction` predicate. `ModuleOutcome` carries the lowered body's `Poly.Runtime.DomainFailure` as `Failure` and renders `Error` from it, so the executor never parses failure text; `FailedGuards` is only the projection `poly_simulate` shows (the real policy name for the action's own `Policy` block, the action's policy names for a path-prefix or unlinked-invoke `Required`, else `[]`), removed with `Error` at X-09. `ParityOutcome.FailureKind` is populated, and its kind, path and guard are compared on both sides.

**Runtime contract: failure status and the concurrency token.** `Poly.Runtime.DomainFailureStatus.Http(kind)` is the only kind→status table: `Unique`, `Link` and `Conflict` are 409, `Cascade` is 500, the other ten kinds are 400, and an unknown kind throws rather than inheriting 400. A host maps a failure through it — it never parses failure text (`MinimalApiGenerator.Host.cs`'s `message.Contains(...)` `FailureStatus` is the shim P-14 deletes) and never prints a second table (#677 g.10). `Link` → 409 means an occupied to-one link only, and `Stage`/`Policy` at 400 are provisional and unruled. `Poly.Runtime.IVersioned { long Version { get; } }` is the optimistic-concurrency token: P-09 binds it and owns the shadow column and the save-time bump, while generated plain C# entities are not thread-safe by contract (#574), so concurrent writes stay the store's concern, not the entity's. ADR: [`docs/decisions/2026-11-12-runtime-contract-package.md`](decisions/2026-11-12-runtime-contract-package.md).

**Runtime contract: the action scope's undo log.** `Poly.Runtime.ActionScope` is the one undo log a lowered action names. `Begin(IStorageJournal?)` opens a root frame — or joins the innermost open one as nested — and takes the journal's mark; `Touch(object)` snapshots an `IActionScoped` entity or a simulator `IDictionary<string, object?>` bag once, before the write; `Create(object, string)` records a created instance with its entity name, readable from `CreatedInstances` while the root is open; `Commit` and `Rollback` complete the frame resolved from the token. `Rollback` on any token of an open frame aborts the whole action (Q1): restores run in reverse touch order, then the journal reverts to the root mark, then the frame closes — always, so there is no poison state and no `Reset`, and failures surface together as an `AggregateException`. A closed ambient frame is a leaked frame and throws; outside a scope `Touch` and `Create` are no-ops, because a domain failure is a returned `DomainResult` and never an exception (Q3). All frame bookkeeping is under one lock over an `AsyncLocal<Frame?>`; entity data is not synchronised (Q2), so parallel roots need distinct journals. `ModuleStoragePort` implements `IStorageJournal` explicitly, and the executor's own mark sits outside the scope's. ADR: [`docs/decisions/2026-11-12-action-scope.md`](decisions/2026-11-12-action-scope.md).

**Lowered action shape.** An action lowers to two methods on the entity's module type: a wrapper at the action's own access that opens an action scope (`Begin`), calls the private `__BodyOf{Action}` method, returns a failed result at once and otherwise commits, with a `finally` that rolls the still-open frame back (a failed result, an exception or a throwing commit); and `__BodyOf{Action}`, which holds the lowered body. The simulator runs the lowered module and the C# printer prints it, so both hosts execute the same wrapper and body; a test that asserts an action's meaning reads the body method (`Poly.Tests/TestHelpers/ActionBodies.cs`), one that asserts its public shape reads the wrapper. `__` is reserved for members and action parameters, so a wrapper local or body method cannot collide with an authored name. No `Touch` is emitted yet: the scope snapshots nothing until L-03c adds it.

**Instance handles, not runtime types.** `ModuleInstance` (`Runtime/ModuleInstance.cs`) is a public record of `(Id, EntityName, Bag)` — the executor's handle onto the dictionary the interpreter already runs. It carries no behaviour: no methods, no dispatch, no lifecycle. That is the line the tenet draws. "There is no instance runtime type" means no second object model with its own semantics; a bag handle is the host's index into the module's dictionary and is not one.
