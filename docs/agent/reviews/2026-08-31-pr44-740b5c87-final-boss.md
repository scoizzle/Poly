## Issues

### Issue 1 -- Severity: suggestion
- File: `Poly/DomainModeling/Runtime/DomainEntityInstance.HostAbi.cs:149–155`, `:189–219`; `Poly/DomainModeling/Runtime/DomainEntityInstance.cs:608–615`
- Description: Pre-existing: `TransitionStage → RunTransitionEffect` (`:149–155`) and `ExecuteSubscriptionEffects` (`:189–219`) run effect sequences with no `PrevalidateUnconditionalCreates` and discard `ExecuteEffect` return values. When a create/create-in collides mid-sequence, `ExecuteEffect` converts the throw to `DomainResult.Failure` (`:608–615`) and the caller discards it, so the transition/subscription completes with prior effects committed and the failure invisible. Not a regression (pre-existing, pre-PR), but the round-3 restore-bag fix for `InvokeActionInternal` does not extend to these shipped paths.
- Suggestion: Route entry/exit/subscription effect lists through `PrevalidateUnconditionalCreates` (or fail the transition/subscription on a non-null prevalidate error), and propagate `ExecuteEffect` failures (call `RestoreActionState` or equivalent). Add a test for a colliding create-in in a subscription effect with a prior assign.
- Status: open
- Reachability: **valid domain, valid inputs** — subscription effects with create + prior assign exist in shipped demos.

### Issue 2 -- Severity: nit
- File: `Poly/DomainModeling/Runtime/DomainEntityInstance.cs:183–189`
- Description: F6 unchanged — the `UniqueConstraint` arm calls `Store.UniqueCollisionMessage` per unique property while that method itself iterates all unique props (`DomainInstanceStore.cs:82–101`); O(n²) with n unique props, and the returned message can name a different property than the outer loop's `prop`.
- Suggestion: Single `UniqueCollisionMessage` call per validation, outside the per-prop loop.
- Status: open
