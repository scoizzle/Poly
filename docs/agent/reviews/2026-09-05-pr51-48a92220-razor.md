## Pass B Issues (bug|suggestion|nit, path:LINE)

- **bug, Poly/DomainModeling/Runtime/DomainEntityInstance.cs:803-805** — Contract-bound actions silently succeed at simulate. `PrependAdapterInvocation` (`DomainToCSharpExporter.Actions.cs:336-354`) prepends `{Contract}Adapters.{Endpoint}(param)` to the module method body; `BindThis`'s `AdapterTypeName` arm rewrites that invoke to `new Block([])`. So `invoke_action` on a bound action runs guards + effects and reports `Success`, and the contract call never happens — a vacuous success. Export is the opposite: `BuildContractAdapterTypeDef` emits a fail-closed adapter that throws `NotImplementedException` (`DomainToCSharpExporter.Actions.cs:363-397`), and `ContractBindingExportTests.BoundAction_Export_MethodBodyNotSilentSuccess` explicitly pins "never a silent no-op". This contradicts `PrependAdapterInvocation`'s own doc ("never dropped, never a silent no-op") and is the clearest instance of "residual silently closed" in the PR: simulate and export diverge exactly where the PR's north star says they must not, and no test covers simulate of a bound action. CORE.md §3.4 does mention "adapter calls skipped", but the mechanism note does not surface the consequence to the MCP user, and it breaks the exporter's fail-loud contract. At minimum it should return `DomainResult.Failure("contract endpoint ... has no implementation")` (mirroring the export), or invoke a registered in-process adapter when one exists.

- **suggestion, Poly/DomainModeling/Analysis/RuntimeAnalysisCache.cs:103-120** — The "first-stage OnEntry prefers a module entry method when present" preference is vacuous. `TryGetEntryMethod` guesses names `OnEntry{stage}` / `{stage}OnEntry` / `OnEntry`, but the exporter never emits such methods — first-stage OnEntry effects are inlined into the constructor (`DomainToCSharpExporter.cs:618-627`). So the `entryStageName` branch at `DomainEntityInstance.cs:661-665` always falls through to `effectPass.LowerActionBody` at create time: a re-lowering residual masked as a "prefer module" mechanism that cannot fire. Either emit an entry method on the module and make the preference real (closing the residual), or delete the speculative name-guessing and document the unconditional execute-time lower. The naming is a guess, not a convention derived from an emitter.

- **suggestion, Poly/DomainModeling/Runtime/DomainEntityInstance.cs:693-736 (with 756-769)** — `ModuleAwareTypeProvider` re-derives the type universe on every `ExecuteEffectList`: it iterates the full module type-def list and `moduleTypes.Analyze(ctx, td)` for each non-entity/non-DomainResult def, then re-builds the runtime entity and re-analyzes it; `EnumTypeNames()` rescans all entities + `GetOrAnalyze` per call. This runs on the invoke hot path *and* on the subscription/transition re-lower paths (where `actionParameters` is null, so the rebuild is pure waste). The module and the derived type provider are stable per (domain, entity); cache the analyzer per entity rather than rebuilding per call.

- **suggestion, Poly/DomainModeling/Runtime/DomainEntityInstance.cs:780-781 + 785-787** — The `Variable v when parameters.ContainsKey(v.Name)` rewrite is applied in *declaration position* too: `Block` rewrites `b.Variables` (line 786), so a local variable declared with the same name as an action parameter is turned into `Member(entity, name)` — a corrupted AST in the declarations list rather than an expression reference. Today it would fail loud via `Interpreter.CompileChecked`, but the rewrite should be scoped to expression positions (a declared local must pass through unchanged; only *references* to params should become bag members). Low reachability, but the guard as written cannot distinguish a shadowing declaration from a param reference.

- **suggestion, Poly/DomainModeling/Runtime/DomainEntityInstance.cs:718-731** — Module-only methods (`Notify*Subscribers`, `Create{Nav}`, `Register*Subscriber`, `Attach*`, `InitializeSubscriptions`, …) are added to the runtime entity as **empty-body stubs**. If a module body ever invokes one that isn't rewritten by `BindThis` (`Notify*Subscribers` is rewritten, so today they are mostly unreachable), it resolves to a silent no-op instead of failing. This is the "stub can mask a missing rewrite" variant of the residual-close problem; prefer fail-closed resolution (a stub whose body is `new Block([])` should at least be distinguishable from a real implementation, e.g. throw on invocation).

- **nit, Poly/DomainModeling/Runtime/DomainEntityInstance.cs:645 (call site :564)** — `args` is a dead parameter of `ExecuteEffectList`: it is passed at `:564` but never referenced in the body (args flow into `_values` via `InvokeActionInternal` `:504-509`). Remove it or document why it's unused (only `actionParameters` feeds `ModuleAwareTypeProvider`).

- **nit, Poly/DomainModeling/Compile/DomainSession.cs:132-136** — Stale doc on `Lower`: "Also caches runtime-shaped named action / OnEntry trees for invoke lookup." Those trees were deleted in this PR; the module-method-body model replaced them. Update the comment to match `RuntimeAnalysisCache`'s new contract.

- **suggestion, src/Poly.DslCompiler/DslCompiler.cs:223-240** — `RequireHttpActionsInModule` is broader than its name and error messages. `BehaviorMetadata.From` (`BehaviorMetadata.cs:30-44`) lists **every** domain entity and action, so the check requires *all* entities/actions to exist in the module, not just HTTP-referenced ones — the "HTTP names entity/action" failures are mis-scoped. It passes today only because the projection always includes every entity; if a future projection omits a non-HTTP entity (e.g. a child/imported contract type), a domain that never referenced it over HTTP would now fail the HTTP build. Scope the check to the actual `HttpSurfaceMetadata`-named entities/actions, or rename/relocate it as a module-completeness invariant.
