### Issue 1 -- Severity: suggestion
- File: `Poly/DomainModeling/Lowering/EffectLoweringPass.cs:668-674`
- Description: Runtime `TryAutoLinkUnambiguousOutbound` (`HostAbi.cs:658-659`) also runs `TryLinkCreateInBackReference` (reverse `Fine.patron`). Emit Type-create only emits collection `Add`. Create-in emit additionally auto-wires reverse via `FindAutoWireBackReference` and registers stage subscribers (`Notify.cs:231-244`). Guide (`poly-dsl-guide.md:73-77`) names reverse as the Type-create semantic, then says export “likewise” emits `_fines.Add` without stating reverse remains runtime/CreateNav-only. Dual-path residue under CORE 3.4. Exported `AssessByType` can leave `fine.Patron` null while `_fines` contains the instance — Rel-exists on the child back-ref disagrees with runtime store edges. Low severity relative to this PR’s F5 claim (CreateNav/**Add**).
- Suggestion: Emit reverse when HostAbi would `TryLinkCreateInBackReference` (pass `this` into `Fine.Create` or assign the singular back-ref), or narrow the guide to “collection Add only.” Optionally register `Register*Subscriber` if Type-create should match CreateNav notify. Add an export oracle that generated `AssessByType` sets or documents reverse.
- Status: open (Razor F7; re-verified)
