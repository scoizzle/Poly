## Issues

### Issue 1 -- Severity: suggestion
- File: `docs/probes/dogfood/hotel.poly:182-191`
- Description: `BookSection` takes a separate `hall: Hall` and stores it on EventHold alongside `section`. Occupancy effects use `section.hall` (`Occupy`/`Vacate` → Mark/ClearChildBusy). A caller can pass a hall that is not `section.hall`; EventHold.`HasHall` becomes true for the wrong space while BusySections move on the real parent. Dogfood test always passes the linked hall (`HotelDogfoodTests.cs:236-243`) so the walk does not lie, but the probe surface allows identity drift.
- Suggestion: `require` hall identity with section’s hall (policy/guard), or drop the hall parameter and bind `hall` from `section.hall` in the create-in. Add a negative test that mismatched hall is rejected or ignored consistently.
- Status: open

### Issue 2 -- Severity: suggestion
- File: `docs/probes/dogfood/hotel.poly:96-98`
- Description: `ClearChildBusy` unconditionally does `BusySections - 1` with no lower bound. Direct invoke (or any unpaired clear) can drive BusySections negative — admitted PR caveat. Dogfood Vacate↔Occupy pairs keep balance (`HotelDogfoodTests.cs:252-274`); not a false-green on the wired path.
- Suggestion: `require` BusySections > 0 (or ChildrenFree negation) on ClearChildBusy; optional analysis/runtime clamp follow-up for Number decrement. Keep tracked until closed.
- Status: open

### Issue 3 -- Severity: suggestion
- File: `Poly.Tests/DomainModeling/HotelDogfoodTests.cs:131-143` (gap vs EventHold)
- Description: Reservation soft-create then Confirm `PartyFits` is proven. EventHold has the same soft-create / Confirm `PartyFits` shape (`hotel.poly:293,298-304`) but no oversized BookHall/BookSection → Confirm failure assertion. Coverage asymmetry, not a lying stay test.
- Suggestion: Mirror the oversized Confirm negative for EventHold (hall or section).
- Status: open

### Issue 4 -- Severity: nit
- File: `docs/probes/dogfood/hotel.poly:315-320`
- Description: `StartHall` requires `not HasSection`; `StartSection` only requires `HasSection` (allows HasHall true). Intentional for BookSection setting both links; document or add a one-line comment so future edits do not “symmetrize” incorrectly and break section holds.
- Suggestion: Comment on EventHold Confirmed stage stating BookSection holds are dual-linked and StartSection must not require `not HasHall`.
- Status: open
