## Issues

### Issue 1 -- Severity: suggestion
- File: `Poly/DomainModeling/Runtime/DomainEntityInstance.cs:617–618`
- Description: After `ExecuteEffectList` succeeds, a declared `-> Entity` action with no matching created child returns `MissingReturn` without `RestoreActionState`. That is `Succeeded=false` while prior assigns/stage/children from the successful effect list remain. Out of the PR’s stated “ExecuteEffectList Failure” contract, but it is a sibling action-failure path that still keeps prior assigns. Reachability on fully analyzed domains is reduced by DMEFF010 (`EffectAnalyzer` requires create for `-> T`); still hit if analysis is absent/stripped or create is present-but-wrong-type.
- Suggestion: Call `RestoreActionState(bagBefore, stageBefore, createdBefore)` before `MissingReturn`, or prove unreachability on domain-bound analyzed invoke and narrow the contract comment.
- Status: open
- Reachability: primarily corrupt/stripped analysis or wrong-type create; not the Item 4 happy Failure path.

### Issue 2 -- Severity: suggestion
- File: `Poly/DomainModeling/Lowering/EffectLoweringPass.cs:426–432`; `Poly/DomainModeling/Runtime/DomainEntityInstance.HostAbi.cs:21–23`; `Poly/DomainModeling/Runtime/DomainEntityInstance.cs:1032–1042`
- Description: Runtime stage transitions emit `TryCatchFinally(..., finally: Notify(stage))` with `EmitInstanceNotify` default true. If the try body (or a later effect in the same action) returns `DomainResult.Failure`, `NotifyTransition` may already have mutated subscribers before `RestoreActionState` resets `CurrentStage`. Restore covers bag/stage/created children (+ their links via `Store.Remove`); it does not undo subscription effect commits. Pre-existing relative to the Unique-gate deletion, but Item 4’s “Failure restores prior assigns” story does not extend to Notify fan-out.
- Suggestion: Track as residual transactional debt — e.g. defer Notify until action Success, or snapshot/revert subscription-visible state; add a test: transition + subscriber assign + later Failure → subscriber bag unchanged.
- Status: open
- Reachability: **valid domain** with subscriptions + transition then Failure in the same invoke.

### Issue 3 -- Severity: nit
- File: `Poly.Tests/DomainModeling/ActionEntityReturnTests.cs:1216–1239`
- Description: `AssignThenNestedRequireFailure_RestoresPriorAssign` asserts `Succeeded=false` and `Flag==0` but not `ErrorMessage` / `FailedGuards`. Weaker than the retargeted IfOnMutatedProperty oracle; still not theater (Flag would stay 1 without restore).
- Suggestion: Assert blocked/require messaging (e.g. AlwaysFail / blocked-by-policy) so a wrong early failure cannot false-green the Flag==0 check.
- Status: open
