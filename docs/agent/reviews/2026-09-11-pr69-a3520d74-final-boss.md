## Issues

### Issue 1 -- Severity: suggestion

- File: `Poly/Analysis/Analyzer.cs:39` (with `AnalysisContext.cs:52`, `AnalysisResult.cs:13`)
- Description: Dropping DistinctBy also dropped `.ToList()`. `AnalysisResult.Diagnostics` aliases the live `AnalysisContext._diagnostics` list (`Diagnostics => _diagnostics`). Metadata is snapshotted (`new NodeMetadataStore(context.Metadata)` at `:37`). `HasErrors` on the result is computed once at construction (`Diagnostics.Any(Error)`). Callers that capture `AnalysisContext` via `Analyze(..., setup:)` and `Report*` after `Analyze` returns would mutate the published list and desync `HasErrors`. Production `Analyze` keeps `context` local; `setup:` sites in this tree are tests and report during setup, not after return. Residual snapshot asymmetry, not fail-open.
- Suggestion: Pass `context.Diagnostics.ToList()` (no DistinctBy) so the report is a frozen report-order snapshot, or document the live alias vs metadata clone in CORE. Do not restore identity DistinctBy.
- Status: open (Razor F1, re-verified)

### Issue 2 -- Severity: suggestion

- File: `Poly/DomainModeling/Queries/DomainQueries.cs:260-275` (also `Poly.Mcp/Tools/DomainTools.cs:276-280,360-377`; `Poly/DomainModeling/Evolution/DomainEvolution.cs:110-112`)
- Description: Downstream counts treat `Diagnostics` as a bag of reports. Two identical Error reports yield ErrorCount 2. Consistent with tip CORE; can mislead agent/UI copy that reads counts as unique issues. `HasErrors` / `ErrorCount > 0` / Compile throw remain correct.
- Suggestion: Document multiset semantics at the analysis API boundary. If MCP/UX needs unique-issue counts, dedupe only at the presentation layer.
- Status: open (Razor F2, re-verified)

### Issue 3 -- Severity: nit

- File: `Poly.Tests/Syntax/Analysis/AnalyzerDiagnosticsTests.cs:5-15`
- Description: Test name claims report **order**, but both reports are identical (`DUP` / same message), so index `[0]`/`[1]` does not distinguish sequence. `Count == 2` proves keep-both (the merge-bar oracle). Order is only weakly evidenced.
- Suggestion: Report two distinguishable messages or codes in sequence and assert `[0]`/`[1]` equality to that sequence.
- Status: open (Razor F3, re-verified). Not a ship block.
