### 2. Flag vs `ShouldInclude`

`AnalysisDiagnosticConfiguration.ShouldInclude` (`AnalysisDiagnosticConfiguration.cs:22-31`): every verbosity arm includes Error (`All`, `InformationAndAbove`, `WarningAndAbove`, `ErrorOnly`; `_ => true`). Filtering cannot drop an Error without also skipping the flag. Filtered severities are Hint/Information/Warning, which never set `HasErrors`.

`NormalizeSeverity` runs before `ShouldInclude` in `ReportDiagnostic`. `TreatWarningsAsErrors` upgrades Warning→Error, then the stored diagnostic is Error and the flag sets — same as master’s list-scan of stored severity. `ReportWarning_DoesNotSetHasErrors` uses `CreateDefault()` (TreatWarningsAsErrors default false).

`AnalysisResult.HasErrors` still `Any(Error)` on the DistinctBy snapshot (`Analyzer.cs:37-39`, `AnalysisResult.cs:13`). DistinctBy key includes Severity, so an Error cannot be collapsed into a non-Error. At least one unique Error remains if any Error was added → result flag true iff context flag true on this path. Dual representation is F3 (drift risk), not a tip skew.
