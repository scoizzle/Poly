- File: Poly/DomainModeling/Runtime/DomainEntityInstance.HostAbi.cs:309
- Description: **False invariant comment.** Says `SubscriptionBodies are export-shaped (UseThis)`. Primary evidence: `RuntimeAnalysisCache.BuildSubscriptionCaches` still lowers with `UseThisReference: false` (lines 339–350) — residual Parameter-rooted twin, as the cache comments correctly state. Same method’s prior comment (line 300) says the opposite (“VM-shaped; BindExportBody no-ops without This”). Protocol: invariant-stating comments are checklists; a lying comment is false advertising. Behavioral impact of calling `BindExportBody` on Parameter-shaped trees is near-identity (no This; void throws not emitted on UseThis:false path — EffectLoweringPass emits `DomainResult.Failure` instead), so this is honesty / future-reader drift, not a demonstrated fail-open. The 5-line HostAbi change is not an ABI break (SetArgs / peer materialize unchanged).
- Suggestion: Narrow the comment to match reality: subscription effects-only cache remains Parameter-rooted / UseThis false (Slice A residual); `BindExportBody` is defensive/no-op for This on that shape. Do not claim export-shaped until a later slice collapses that twin.
- Status: open

### Issue 2 -- Severity: suggestion
- File: Poly/DomainModeling/Runtime/DomainEntityInstance.cs:958 (`RewriteVoidFailClosedThrow` default)
- Description: `BindThis` fail-loud on unknown node kinds (`InvalidOperationException` at :1122–1123). `RewriteVoidFailClosedThrow` uses `_ => node` — soft skip. If EffectLowering (or a future node) nests `ThrowStatement(new InvalidOperationException)` under an unhandled wrapper that `BindThis` still walks, the void fail-closed throw could reach the VM unrewritten (VM has no 1-arg IOE ctor per the method’s own comment). Current EffectLoweringPass emits `ThrowStatement` for void UseThis fail-closed; create-in illegal OnEntry coverage exists elsewhere and CI is green — so today’s shipped shapes appear covered. Soft default is the weaker sibling.
- Suggestion: Align with `BindThis`: throw on unknown kinds, or add explicit cases for every node EffectLowering can emit. Add a unit oracle that plants `ThrowStatement(New IOE(...))` under `BindExportBody` and asserts `Return(DomainResult.Failure(...))` shape.
- Status: open

### Issue 3 -- Severity: suggestion
- File: Poly/DomainModeling/Runtime/DomainEntityInstance.cs:762–770
- Description: **Sibling path skips throw rewrite.** Prefer `TryGetEntryExitBody` → `BindExportBody` (includes `RewriteVoidFailClosedThrow`). Fallback `TryGetExitMethod` / `TryGetEntryMethod` → `BindModuleMethodBody` only (`BindThis`, no rewrite). Reachability on a normal GetOrLower populate is low: when a batch is non-empty, EntryExitBodies and the module method are filled from the same `BuildStageBatchMethodExport` call. Fallback becomes interesting if EntryExitBodies is cleared (test hooks) or a name collision leaves a pre-existing module method without a matching shared Body — void IOE throws would then hit the VM.
- Suggestion: Route module-method entry/exit fallback through `BindExportBody` (or share `RewriteVoidFailClosedThrow` after `BindModuleMethodBody`).
- Status: open
