## Summary

The PR removes the special VM `StoreQuantifier` path and lowers `any`/`all`/`none`/`count` to ordinary `ForEachLoop` + `BreakStatement` tree nodes for both simulate and the C# export. The shape is uniform: `result = init; foreach (itemN in <nav>) { <body>; if (<match>) { result = …; break; } }`, with `all` additionally gated by `sawItem` so the empty collection is false (`DomainExpressionLoweringPass.cs:457-506`). Action effect quantifiers use one lowered module for simulate and print (`LowerExpressionToMethodBody` / the cached action module); policies keep a residual twin (`UseThisReference:false` vs `true`) exactly as `RuntimeAnalysisCache.cs:428-468` documents.

Local-name generation is now one `LocalNames` per method (`LocalNames.cs:6-9`), shared by `EffectLoweringPass` and every nested quantifier pass via `LoweringContext.Names` (`LoweringContext.cs:85-109`), and across stage-dispatch branches and the entity-level tail (`DomainToCSharpExporter.Actions.cs:110-146`). I found no name collision: nested quantifiers call `_names.Next` on the same generator (`DomainExpressionLoweringPass.cs:525-529`). Statements-before-value plumbing (`LoweredExpression.Before`/`Combine`, `LoweredExpression.cs:21-38`) is consistently applied at every effect boundary I checked (`Assign` :283, `Conditional` :830/:842, `InvokeAction` :664/:673, `ForEachInvoke` :763-770, create factories :1147, path-prefix :192-199, short-circuit :349-357).

The two new behavior changes tied to the quantifier work are coherent: dictionary collection-nav reads are now outbound-only and fail closed without a store (`DomainEntityInstance.Dictionary.cs:24-25`, `DomainEntityInstance.Runtime.cs:389-398`, `DomainInstanceStore.cs:425-440`), and Boolean bag values are coerced only for `0/1` (`DomainEntityInstance.cs:402-410`, pinned by `Create_BooleanProperty_CoercesOnlyZeroAndOne`), while policy truthiness keeps the full nonzero rule (`:412-419`).
