## Summary

The PR removes the store-job quantifiers: the `AnyRelated/AllRelated/NoneRelated/CountRelated` host methods, the `DomainExpression` that was packed inside a `Constant`, and the per-item re-lower/compile/execute. In their place, `any/all/none/count … where` now lower to ordinary `Assignment`/`ForEachLoop`/`IfStatement`/`BreakStatement` nodes over `Member(subject, Nav)`. The loops are hoisted into a `Block` ahead of the value. For **policies**, this works: the simulator and the compiled printed C# agree, backed by a real test that compiles, loads, and invokes the generated code. The new `Block` return shape is only unpacked at the policy sink, though. Every `EffectLoweringPass` sink puts the `Block` in expression position, so a valid domain with `if (any … where …)` or `assign N to count … where …` in an action now exports C# that does not compile, where it used to fail loud (F1). Losing the store-less throw makes quantifiers return vacuous results, `none` included, while `Rel exists` still throws on the same instance, and CORE still documents fail-closed (F2).

## Assigner points

**(1) Collection read vs outbound-only (self-referencing relationships).** Evidence:

- `DomainInstanceStore.GetRelatedInstances` is **bidirectional**: it returns targets when the instance is the source and sources when it is the target (`Poly/DomainModeling/Runtime/DomainInstanceStore.cs:411-423`).
- The new read, `TryGetCollectionNavigation` (`DomainEntityInstance.Runtime.cs:392-394`), and the **old** quantifier read, `GetOutboundRelatedInstances` (`:425-427`), make the **same** call with the **same** target-type filter. The old doc says "Outbound links only … Reverse-side navigate is rejected" (`:398-401`), but that was already false whenever source type == target type.
- Probe: a scratch test that was never committed and has been deleted. It builds `Employee` with `reports: many Employee`, linked `mgr → emp`, and evaluates `any reports where Flag` directly with constructors, which bypasses analysis. Results were **identical on master and on bc3423b6**: `emp` (no outbound reports) returns **True** because it sees `mgr` through the inverse link, and `count` returns the same.
- DSL-authored domains cannot reach this. The analyzer rejects it with "Quantifier on self-relationship 'reports' is not supported yet." (`Poly/DomainModeling/Analysis/PolicyConstraintAnalyzer.cs:198`). The probe confirmed that evolve fails.
- **Disposition: neither a regression nor a correction.** The inverse-link leak for self-relationships is pre-existing, and the PR keeps it. It is latent, gated by the analyzer, and the printed C# (`this.Reports`, outbound only) would disagree with the simulator if the gate were lifted. Filed as follow-up F6 (suggestion). It does not block SHIP.
- Differences the new read does introduce: no throw without a store or domain (F2), and ManyToMany is now allowed where the old read threw "not supported yet" (`:414-417`). The second is a quiet widening. The printed C# handles ManyToMany collections the same way, so I am not filing it.

**(2)** `RuntimeAnalysisCache.cs:433` still says "VM StoreQuantifier path requires UseThisReference:false". That is stale, known, and belongs to P3-B. Noted here and **not a blocker** (Pass B filed it as a nit; folded into this note).

## Hand-editability gate: **NO**

Could Scot open these files cold and change them by hand? Not safely yet:

- **Twin sinks.** `Lower` now returns either a value or a `Block` of loops with the value last, and each caller has to know that. One caller (`AsBooleanMethodBody`) does. Seven do not (F1). If you add a new sink by hand, you will hit this silently.
- **Hidden mutable state.** The recursion correctness depends on swapping fields in and out: `_quantifierLoops`, `_quantifierLoopVariables`, and `_enumPropertyNames`, which is now non-`readonly` (`DomainExpressionLoweringPass.cs:34`, `:45-47`, `:425-447`). Calling `Lower` instead of `Route` from inside the pass silently throws away the outer loops; the commit message says so, the code does not guard it (F3).
- **Source order is not trace order.** `Ready and (any lines where Open)` runs the loop *before* `Ready`, and `and`/`or` no longer short-circuit around quantifiers. Stepping through the interpreter no longer follows the source (principle zero) (F3).
- **Docs claim more than the code does.** CORE §3.1 (`docs/CORE.md:137`) still says quantifiers use `GetOutboundRelatedInstances` and fail closed without a store (F2/F5). The comment "Lower puts the loops in front of the expression" (`:339-343`) holds only at the policy sink. `AsBooleanMethodBody` (`DomainToCSharpExporter.Actions.cs:475`) does nothing boolean: it turns the last node into a return (F4).
- **Tests.** The brace-matching method extractor is copy-pasted (`DomainToCSharpExporterTests.cs:3067`, `QuantifierLoopTests.cs:110`, plus older copies at `:2769/:2927/:2969`). There are two reflection `Create` harnesses (`DomainToCSharpExporterTests.cs:3151`, `QuantifierLoopTests.cs:170`). The negative asserts check strings from the deleted implementation (`DoesNotContain("AnyRelated")`, `("store-aware")`, `:3080-3082`), which reads like agent paperwork rather than a contract (F4).
- Positive: the deletion side is a clear readability win. The removed per-item lower/compile/execute and the `object? body` ABI were worse to hand-edit than a plain `foreach`.

## Issues

### F1 -- Severity: bug
- File: Poly/DomainModeling/Lowering/EffectLoweringPass.cs:810 (also :204 assign value, :644/:749 invoke args, :1012/:1026 probe conditions, :1094 create initializers, :1214 enum-aware value); source of the new shape at Poly/DomainModeling/Lowering/DomainExpressionLoweringPass.cs:113-115
- Description: `Lower` returns `Block([...loops, value])` whenever an expression contains a filtered quantifier. Only the policy sink unpacks it (`DomainToCSharpExporter.Actions.cs:468-478`). `EffectLoweringPass` puts the `Block` straight into `IfStatement.Condition` / `Assignment.Value`, and `CSharpGenerator` prints it as a statement block. I reproduced this on a valid domain whose analysis has no errors:
  `Bin: entity { Active: Boolean default(false)  N: Number default(0)  widgets: many Widget  Mark: action { if (any widgets where Active) { assign Active to true } }  Tally: action { assign N to count widgets where Active } }`.
  The export emits `if ({ var any0 = false; foreach (var item0 in this.Widgets) {…} any0; })` and `this.N = { … }`. Roslyn reports CS1525/CS1026/CS1513. Pass B reproduced the same output independently through MCP `export_domain_to_csharp` on the `Item4FailBeforeMutateTests` domain. On master, both simulating and exporting this domain threw `NotSupportedException` (probe). The PR fixes simulation, which now works: `Mark` sets `Active=True` and `Tally` gives `N=1`. But export went from **loud failure to silently emitting invalid C#**, and it contradicts the head commit message ("printed a statement block in expression position … Lower puts the loops in front").
- Suggestion: make the shape explicit. Have `Lower` return `(IReadOnlyList<Node> Prelude, IReadOnlyList<Variable> Vars, Node Value)`, or add a single `LowerInto(List<Node> statements, …)`, so that every sink has to place the prelude in front of the statement that reads the value. Delete `AsBooleanMethodBody` in favor of that one path. Add export+Roslyn-compile tests for action `if`, `assign … count … where`, and a create initializer, plus a sim/print agreement case for an action.
- Status: open

### F2 -- Severity: bug
- File: Poly/DomainModeling/Runtime/DomainEntityInstance.Runtime.cs:387-390; test Poly.Tests/DomainModeling/DomainEntityInstanceTests.cs:3068 (renamed from `EvaluatePolicy_Quantifier_WithoutStore_Throws`); contract docs/CORE.md:137

The old path threw (`GetOutboundRelatedInstances`, `:419-422`), and the PR inverted the test to accept the new result instead of keeping the oracle. CORE §3.1 still says "Fail closed without store/domain for those forms". Reachability: calling the public `EvaluatePolicy` on a store-less instance is legal, and the test does exactly that. MCP/product instances are always store-added, which limits the blast radius but not the contract break.
- Suggestion: restore fail-closed. In `TryGetCollectionNavigation`, throw the same "Cannot resolve relationship target without a DomainInstanceStore" error when `Store is null || Domain is null`. Revert the test to `Throws<InvalidOperationException>` and add `none`/`all` variants. If the intent really is to change the contract, get Scot's decision, update CORE:137 in the same change, and make `exists` agree.
- Status: open

### F3 -- Severity: suggestion (hand-editability gate)
- File: Poly/DomainModeling/Lowering/DomainExpressionLoweringPass.cs:104-116, :34, :45-47, :424-447
- Description: the quantifier hoist depends on mutable fields that are saved and restored around recursion. `_enumPropertyNames` lost `readonly` just to be swapped. Re-entering the public `Lower` from inside the pass (the natural move for a hand editor) resets `_quantifierLoops` and silently drops the outer loops. Hoisting also reorders evaluation against the source: loops run before the left operand of `and`/`or`, short-circuit is lost, and nested body loops run for every outer item even when the rest of the body would short-circuit. Stepping through the interpreter no longer follows the DSL text, which cuts against principle zero.
- Suggestion: with F1's explicit prelude return, the fields go away. Pass the target entity's enum map as an argument instead of mutating the field. If source-order tracing matters, lower `any/all/none` in expression position to a node the VM and printer both treat as an expression (e.g. a local-function call or a `Conditional` over a pre-computed variable placed right before the enclosing statement), and document which one was chosen.
- Status: open
