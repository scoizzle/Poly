## New findings

### W1: Severity: bug. An OnEntry transition chain emits two nested `previousStage` locals, so printed C# fails to compile (CS0136).
- File: `Poly/DomainModeling/Lowering/EffectLoweringPass.cs:506-513` (declares `Variable("previousStage")` per transition) and `:613` (`new Block(nodes, [previousStage])`).
- Repro:
  ```
  WorkItem: Draft { Prep → Ready }, Ready: stage { entry { transition to Done } }, Done
  Board: items: many WorkItem; when all items Ready, Done { assign Fires to Fires + 1 }
  ```
  The generated `WorkItem.Prep()` contains `var previousStage = this.CurrentStage;` and then, inside the inlined entry block, a second `var previousStage = this.CurrentStage;`. Roslyn reports `error CS0136: A local or parameter named 'previousStage' cannot be declared in this scope`.
- Impact:
  - On base `987738ef` the same model prints and compiles, and the printed fire counts are 0, 1.
  - Simulate at head is correct (0, 1), so print and simulate diverge again on a product-surface model. That violates principle zero.
  - It triggers whenever the outer and inner stages both have post-transition notify nodes, meaning both are watched by any subscription (Each, Any or All).
- Not covered by any committed test. Neither agreement test has an entry chain.
- The OpenCode pass found this independently.
- Suggestion: give each transition's capture a unique name, or scope it so the inner block doesn't shadow the outer one. Don't hoist a single variable: the outer notify must still see the outer pre-stage. Add the chain to `WhenAllSimulatePrintAgreeTests` so both paths are checked.

### W2: Severity: suggestion (hand-editability; blocks ship). The notify argument is injected by name-sniffing a node another file built.
- File: `Poly/DomainModeling/Lowering/EffectLoweringPass.cs:574-590`; builder at `Poly/DomainModeling/Lowering/DomainToCSharpExporter.cs:363-373`; `StageTransition` doc at `EffectLoweringPass.cs:493-499`.
- Description:
  - The exporter builds `this.Notify{Stage}Subscribers()` with zero arguments. `EffectLoweringPass` then pattern-matches any `Invoke` whose member name starts with "Notify", ends with "Subscribers" and has zero args, and rebuilds it with the pass-local `previousStage` variable.
  - Three things must agree without any link between them: the method-name convention, the local name `"previousStage"` (`EffectLoweringPass.cs:509`), and the parameter added at `DomainToCSharpExporter.cs:455-457,483`.
  - The `else` branch still emits zero-arg calls, and those can no longer compile because every `Notify{Stage}Subscribers` now takes a parameter.
  - The `StageTransition` doc doesn't mention the capture or the rewrite.
  - W1 comes from exactly this hidden coupling. A cold reader of the exporter would not know the argument gets added somewhere else.
- Suggestion: have the exporter build the invoke with the argument node (or pass a factory), delete the name-sniff branch, and document the capture in the `StageTransition` summary.

### W3: Severity: suggestion (hand-editability; blocks ship). A test doc comment is now false.

After `5e817061` and `76ab9346` the store has no Any/All logic (`DomainInstanceStore.cs:532-538`), and the set conditions live in the lowered handler. The OpenCode pass found this; I confirmed it.

### W4: Severity: suggestion (behavior change, fail-closed; needs a decision or a test). A path-prefix used as a comparison operand now throws when unlinked.
- File: `Poly/DomainModeling/Lowering/DomainExpressionLoweringPass.cs:152-154` ("Value leaves stay the hop").
- Description:
  - `Age < advisor Age` with an unlinked `advisor` now throws `InvalidOperationException: Member 'Age' requires a non-null instance` from `EvaluatePolicy`. On base `987738ef` it was **False** (probe).
  - Print emits `this.Age < this.Advisor!.Age` and NREs, so the two paths now agree on failing, which is consistent with principle zero.
  - It is fail-closed, not fail-open. But bare `evaluate_policy` / stage-policy results change from False to an exception, and no test or doc records the choice.
- Suggestion: either lift the guard to the enclosing predicate when an operand contains a path-prefix (so the whole comparison is false, as on base), or add a test plus a one-line doc saying operand path-prefixes fail closed by throwing.
