## F36 (bug, regression from 59601d4e): value hops inside a quantifier body are guarded on the outer `this`

- **Where**: `Poly/DomainModeling/Lowering/DomainExpressionLoweringPass.cs:432-433`. The fallback walks `expr.Children` with the **outer** `subject` and `subjectPath`. A quantifier's `Children` is its body, so an item-scoped hop is treated as a hop on the comparison's entity.
- **Repro** (reached through analysis; `PolicyConstraintAnalyzer` accepts it):

  ```text
  Product: entity { Stock: Number }
  Item: entity { Qty: Number   product: Product }
  Order: entity { Total: Number   items: many Item
    P: policy { (count items where Qty < product Stock) > 0 } }
  ```

  The inner lowering is right: `item0.Product != null && item0.Qty < item0.Product!.Stock`. But the outer comparison prints `return this.Product != null && count1 > 0L;`.
  - Order has no `product`: print fails with **CS1061** "'Order' does not contain a definition for 'Product'", and simulate **throws** "VM compile rejected: Type 'Order' does not contain a member named 'Product'". The same happens for `Total < count items where …` and `(any items where …) == true`.
  - Order also has an unrelated `product: Product`: it compiles, and simulate silently returns **False** when the right answer is True (the item's Qty 1 < Stock 10, but the order's own product is unlinked).
  - On **master** the same models print and compile, and simulate returns **True**.
- A bare `any items where Qty < product Stock` (no outer comparison) is unaffected.
- The walk also descends into `DateOperation` children and `OwnedAccess.Inner` with the outer subject. `OwnedAccess` is programmatic-only (the DSL never folds it), so the only DSL-reachable shape I found is the quantifier one.
- **Direction**: stop the walk at scope-changing nodes (quantifiers, `OwnedAccess`, library forms), or re-root the subject the way `LowerQuantifierBody` and `OwnedAccess` (`:151-152`) do. Add the repro as an agreement test.

## F37 (bug, regression from 59601d4e): peer-binder operands get a `this.<Binder> != null` guard

- **Where**: `DomainExpressionLoweringPass.cs:421-428`. `RelationshipNavigation` routes a name found in `_parameters` to the binder parameter (`:154-164`), but `CollectValueHops` never consults `_parameters`. It treats the binder name as a to-one on `this`, and `ResolveNavName` PascalCases it.
- **Repro** (analysis accepts it):

  ```text
  Customer: entity { Balance: Number  Flag: Boolean default(false)  orders: many Order
    when orders Active as order { if (Balance < order Total) { assign Flag to true } } }
  Order: entity { Total: Number  Draft: stage { Activate: action { transition to Active } }  Active: stage {} }
  ```

  At head this prints `if (this.Order != null && this.Balance < order.Total)`, and the print fails with **CS1061** "'Customer' does not contain a definition for 'Order'". If a member named `Order` existed, the guard would test the wrong object. On **master** it prints `if (this.Balance < order.Total)` and compiles.
- **Direction**: a hop whose name is in `_parameters` is the binder, not `this.<Rel>`. Either skip the guard (a non-null binder is the subscription contract) or guard the parameter node itself. Pin it with a subscription agreement test.
