## Summary

The PR drops `BindThis`, the stage-enum rewrite, the Notify rewrite, the `DomainResult.Success(value)` rewrite, and the ~80-line `RewriteVoidFailClosedThrow` walker. Here is what replaces each:

- **`this`**: simulate now compiles the printed `ThisReference` bodies. `CompileBody` + `AnnotateThisReferences` (`DomainEntityInstance.cs`) type `this` as the entity.
- **Enum members**: `RuntimeEnumTypeProvider` resolves stage and domain enum members to string constants.
- **Notify**: printed `Notify{Stage}Subscribers(previousStage)` calls reach the store through runtime stubs (`DomainEntityInstance.Runtime.cs:153-165`) and `TryNotifyStageSubscribers` (`InvokeNamed.cs:28, :75-90`).
- **What is still rewritten**: `BindForSimulate` rewrites only action params, subscription `previousStage`, unbound adapters, and the void IOE throw. `AsVoidResultBody` adds a trailing success return so a Failure out of a void body is visible.
- **Lowering**: `Comparison` now ANDs `rel != null` for each to-one value hop (`DomainExpressionLoweringPass.cs:400-424`).

My probes confirm:
- `when any` / `when all` fire counts are identical to master and to print.
- Unlinked single-hop comparisons are False on both paths.
- Master's silent success on an on-entry range violation in simulate is fixed.

The dominant risk is F1. Oracle strength is moderate. Of the 5 new tests, only 2 fail on master: I copied them onto master and ran them (see F4).

## Issues

### F1 -- Severity: bug (sibling path of the new guard; invariant comment violated; reproduced by execution)
- File: Poly/DomainModeling/Lowering/DomainExpressionLoweringPass.cs:400-405, :417-424
- Description: `CollectPathPrefixValueHopNames` records the outer `RelationshipNavigation` and returns, and the guard is `this.<Outer> != null` only. Repro:
  ```poly
  Mentor: entity { Age: Number }
  Advisor: entity { Age: Number  mentor: Mentor }
  Customer: entity { Age: Number  advisor: Advisor
    P: policy { Age < advisor mentor Age } }
  ```
  With the advisor linked and the mentor unlinked, simulate `EvaluatePolicy(P)` throws "Member 'Age' requires a non-null instance." and the printed `P()` throws a `NullReferenceException`. With the advisor unlinked, both return False, which is the PR's fix; master threw on both paths.
  The folded path-comparison form `advisor mentor Age > Age` is guarded per hop and returns False on both paths. So the behaviour depends on which side of the comparison the path is written on. `require P` still fails closed through `WalkPathPrefixRequireGuards` ("requires a linked 'mentor'"), which is the sibling that already walks every hop.
- Suggestion: collect the full to-one chain and emit `h1 != null && h1.h2 != null && …`, reusing the require-guard walk. Add simulate+print cases for an unlinked inner hop and for both hops linked.
- Status: open
