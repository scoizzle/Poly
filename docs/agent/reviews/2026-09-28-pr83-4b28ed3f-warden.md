## Findings

### F1: bug (pre-existing, A3 residual). A path-prefix hop does not retarget `SourceEntityName`, so a quantifier after the hop binds on the wrong entity.
- **Code**:
  - `RelationshipNavigation` routes the leaf with `Route(rn.TargetProperty, new NullForgiving(relMember))` (`DomainExpressionLoweringPass.cs:179`). That changes `_currentSubject` to `this.Team!` but keeps `_context.SourceEntityName` = the source entity (`Dept`).
  - A quantifier in the leaf then calls `ResolveRelationshipTarget("workers")` (`:268-275`), which looks up `workers` on **Dept**.
  - `LowerQuantifierBody` (`:492-507`) then picks the enum map of whatever it found. If it found nothing, it keeps the outer (`Dept`) map.
- **Probe**: scratch TUnit test at head. The model is PR 79's `PathPrefixHop_QuantifierOnTarget` shape plus enums.
  ```
  WorkerState: enum { Idle, Busy }   TempState: enum { Busy, Idle }   TeamState: enum { Done, Busy }
  Worker: entity { State: WorkerState }   Temp: entity { State: TempState }
  Team: entity { Active: Boolean  State: TeamState  workers: many Worker }
  Dept: entity { team: Team  workers: many Temp
    P: policy { team Active == any workers where State == "Busy" } }
  ```

  | Case | simulate | printed body | print |
  |---|---|---|---|
  | Team linked, Active, Worker Busy, `Dept.workers → Temp` (collision) | True (correct) | `if (item0.State == TempState.Busy)` | **CS0019** `WorkerState` vs `TempState` |
  | same, Worker Idle | False (correct) | same | **CS0019** |
  | no `Dept.workers` | True (correct) | `if (item0.State == "Busy")` | **CS0019** `WorkerState` vs `string` |
  | master `9db8868f`, same models | True / True | same wrong enum or string | CS0019, same |

- **Controls (correct at head)**:
  - A direct quantifier with the same navigation name on two entities (`Team.P: any workers where State == "Busy"`, with `Agency.workers → Temp`) prints `WorkerState.Busy`, and both paths return True.
  - A nested quantifier (`any workers where (any tasks where State == "Done")`, with a colliding `Team.tasks → Other`) prints `TaskState.Done`, and both paths return True.
  - So explicit passing works wherever a quantifier retargets. Only the path-prefix hop is missing.
- **Reach**: `PolicyConstraintAnalyzer.ValidateRelatedPropertyAccess` (`PolicyConstraintAnalyzer.cs:311-335`) recurses into quantifier bodies and checks their properties against the *hop target* (and the outer item for nested quantifiers). It rejects `State` unless `Team` (or `Worker`) also has a `State` property. That analyzer check is also pre-existing and wrong, and it narrows F1's reach (see "Not counted").
- **Hand-edit gate**: `LoweringContext.cs:80` says "Current-subject entity type name" and `DomainExpressionLoweringPass.cs:63-64` says "the current-subject entity". A cold reader would trust that it follows `_currentSubject`. It does not on the hop (`:179`, via `Route` at `:214-218`).
- **Direction**:
  - In `RelationshipNavigation`, resolve the hop target with `ResolveRelationshipTarget(rn.RelationshipName)`.
  - Lower the leaf with that name as `SourceEntityName`, and with that target's enum map, as `LowerQuantifierBody` already does for quantifiers. The simplest route is a nested pass that shares `Names`.
  - Add the collision model above to `QuantifierLoopTests` with simulate and print (Roslyn compile).
  - Optionally fix the analyzer walk so quantifier bodies validate against the quantifier's item entity.

### F2: suggestion (hand-edit). The `Subject` doc on the expression pass describes a field the pass ignores.
- `DomainExpressionLoweringPass.cs:56-58`: "The instance root is `LoweringContext.Subject` (module bodies pass `ThisReference`)."
- The pass has no read of `context.Subject`. Grep shows only `_currentSubject`, which is set from the `subject` argument at `:105`.
- Before this PR, `TypeNameOf(context.Subject)` at least read its type. Now nothing does, and the PR added two lines to this same doc block.
- **Direction**: say the root is the `subject` passed to `LowerExpression`/`Lower`, and that `LoweringContext.Subject` is used by `EffectLoweringPass` only.

### F3: nit. The path-prefix comment uses "value" for two different things.
- `:166-169` reads "A value-only leaf is `rel != null && <leaf>` … Value leaves stay the hop."
- The first sentence is about predicate leaves with `Statements.Count == 0` (`:183-184`). The second is about non-predicate leaves (`:180-181`).
- Rename the first to "a statement-free predicate leaf". The backout removed the sentence that used to reconcile the two.

### F4: nit. `EffectLoweringPass` silently overwrites `SourceEntityName`.
- `EffectLoweringPass.cs:52-53` does `… with { SourceEntityName = entity.Name }`. Every production caller passes the matching entity, so the behavior is right.
- One ctor-doc line ("the effect's entity always wins") would stop a cold editor from wondering why a supplied value has no effect.
