## Findings

Severity: bug = wrong or misleading result; suggestion = fix soon, by hand; nit = polish. No bugs.

### Suggestions

- **F106 [suggestion] The "twice on one session" half does not re-lower.** `EmitGoldenTests.cs:85-90`: `session.Emit(domain, analysis)` twice on the same `Domain` object. `DomainSession.Lower` goes through `RuntimeAnalysisCache.GetOrLower` (`DomainSession.cs:153`), which returns the cached module for that `Domain` (`RuntimeAnalysisCache.cs:99-103`, `ConditionalWeakTable<Domain, Holder>` at `:40`, reference equality). So that half pins the C# generator and the catalog on one session; nondeterminism inside lowering is only caught by the separate-sessions half (which does re-lower, because each `CompileSample` builds a fresh `Domain`). The card's wording is met; the test comment should say what each half proves, or the one-session half should re-evolve on the same session to get a fresh `Domain`. (Mill finding 1 called the whole test a tautology; my mutation tests show it is not.)
- **F107 [suggestion] The sample list is hand-maintained and skips three compilable non-archive samples.** `EmitGoldenTests.cs:24-35`. Skipped: `docs/probes/smoke/smoke.poly`, `demo/live/domain.poly`, `demo/live/checkout.poly` (all compile and reproduce). `nested-invoke-type-mismatch.poly` is correctly absent (it is an invalid domain). No comment states the rule ("probe samples that compile"), and nothing fails when a new `.poly` is added under `docs/probes` or `demo/live`. Fix: add a short comment with the rule, and a guard test that enumerates those folders and asserts each file is either in `SampleDomains()` or in a short named "expected not to compile" list; or add the three samples with goldens.
- **F108 [suggestion] Regeneration is not surfaced where a red test shows up.** (a) `AssertGoldens` failures print only the diff or the set mismatch ("Expected to be equivalent to [produced names] ... collection has 4 items but expected 5"); neither says `POLY_UPDATE_GOLDEN=1`. (b) A sample with no golden folder throws a raw `DirectoryNotFoundException` (`EmitGoldenTests.cs:130`; reproduced by deleting `EmitGolden/clinic`). (c) The procedure is a one-line comment on a private method (`:117`). Fix: put the command in the class summary, and wrap the assertions so the message ends with "if this change is intended, run with POLY_UPDATE_GOLDEN=1 and review the git diff of EmitGolden/"; treat a missing folder as an empty set with the same message.

### Nits

- **F109** `git diff --check` flags `crm-dslcompiler/demo.http.golden:316` (blank line at EOF). It is the product's output (`demo.http` ends with `\n\n`), so the snapshot is right and trimming it would make the test fail. `.editorconfig` has `insert_final_newline = false`, and there is no rule for `*.golden`; note it in the class header (or add a `.gitattributes` line `*.golden -whitespace` in a later non-test change).
- **F110** `AssertSameOutput` (`:145-147`) normalizes CRLF to LF on both sides, so the reproducibility test would not notice a generator that flips line endings. Normalizing the golden side is a reasonable guard for Windows checkouts; the two-fresh-outputs comparison could use raw strings.
- **F111** `Crm_DslCompilerHostFiles_MatchGolden` keeps DslCompiler files whose names are not in the test's own `Emit` output (`:63-68`). It yields exactly the three host files today. It would silently skip a host file that reused an entity file name, and it never compares DslCompiler's own copy of the entity files to the Emit goldens (the two sessions use different libraries and seeds, so equality is not guaranteed). A one-line comment saying what is and is not pinned would do.
- **F112** `FindRepoRoot` (`:152-160`) is a copy of the helper in `DslCompilerCompileOracleTests.cs:217-225`, including its check for `Poly.sln`, a file this repo no longer has (it uses `Poly.slnx`); only the `docs/CORE.md` branch can match. Share one helper and drop the dead check, at the next edit of either.
- **F113** Update mode deletes `.golden` files not produced (`:122-126`), which is right for renamed outputs, but a sample removed from the list leaves its whole folder behind, and nothing flags it. Add it to the F107 guard or say so in a comment.
