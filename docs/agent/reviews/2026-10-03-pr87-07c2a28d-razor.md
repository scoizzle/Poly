## Summary

`ParityScenario.AssertAgree(Action<ParitySide>)` runs one scenario lambda on a simulate side (`DomainEntityInstance.Create`, `DomainInstanceStore`, `InvokeAction`, `EvaluatePolicy`) and a printed side (the Roslyn-compiled output, driven by public reflection), recording per step: success, failure message, exception type, and a state map (every property, nav link counts, `Stage`, policy answers). It asserts the two outcome lists equal step by step. Five rows in `ParityTests.cs` use it (create-fail via entry effect, action-fail via assign range, stage transition, `Patron_HasOverdueLoans` policy, create-in-action linked children). `PrintedCSharpCompiles` compiles 10 sample domains.

The core idea works: sabotaging either side makes the right row red (mutation table below). The problems are at the edges, where the helper can say "agree" without having compared what the label says, and where "every sample domain" is not actually enforced.

### Issue F2 -- Severity: bug
- **File**: `Poly.Tests/TestHelpers/ParityScenario.cs:84` (with `:64-65`)
- **Description**: `Record` snapshots `Current ?? value`, but `Current` is only updated after `Record` returns. For the second and later creates, the recorded state is the *previous* entity's, so the newly created entity's property values are not compared until a later step reads them (a trailing create is never compared).
- **Repro**: scenario `Create("Kid", ("Name","a")); Create("Kid", ("Name","b"))` over `Kid: entity { Name: Text }` → `outcomes[1].State["Name"] == "a"`.
- **Suggestion**: Pass the freshly created entity to the snapshot for create steps (set `Current` before snapshotting, or snapshot `created ?? Current`).
- **Status**: Open

### Issue F3 -- Severity: bug
- **File**: `Poly.Tests/TestHelpers/ParityScenario.cs:90-94`
- **Description**: `catch (Exception)` records any exception as an "outcome" with empty state, including harness faults. Both sides hitting the same harness bug (e.g. null `Current`) compare equal and the row is green.
- **Repro**: `AssertAgree(side => { side.Create("Widget"); side.Invoke("Nope"); })` with a domain where this is not a valid action → both sides record `NullReferenceException: Object reference not set to an instance of an object.` and the assert passes.
- **Suggestion**: Catch only the exception types the domain operations are allowed to raise (`InvalidOperationException` and the printed side's unwrapped equivalent), or rethrow `NullReferenceException`/`ArgumentException`/reflection-binding errors; throw a clear harness error for unknown actions/entities.
- **Status**: Open
