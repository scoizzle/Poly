## Findings

Severity: bug = wrong or misleading result; suggestion = fix soon, by hand; nit = polish.

### Bug

- **F121 [bug] `Artifacts` returns the private `List<Artifact>`; the catalog can be edited through a cast, which breaks the "no public remove or replace" rule and desyncs `Find`.** `ArtifactCatalog.cs:8, 12`: `private readonly List<Artifact> _artifacts` and `public IReadOnlyList<Artifact> Artifacts => _artifacts;`. A caller can write `((IList<Artifact>)catalog.Artifacts).Clear()` (or `.Remove`, `.Add`, an indexer set). Probe on the head: runtime type is `List<Artifact>`; after `Clear()`: `Artifacts.Count` 0, `ToText()` `""`, `Find(id)` **still returns the artifact**, and `Register` of the same id **throws** "already registered", so the two stores disagree and the entry cannot be re-added. The card's Scope says "no public remove or replace (explicit rule, tested)" and the plan's ownership rule says nothing edits or deletes an artifact. The repo already wraps lists this way elsewhere (`Block.cs:56-57`, `.AsReadOnly()`). Fix: `public IReadOnlyList<Artifact> Artifacts => _artifacts.AsReadOnly();` (or store a `ReadOnlyCollection` field); keep a cached read-only wrapper if allocation matters. I applied this in a scratch worktree: all 7 existing catalog tests still pass, and a new test `((IList<Artifact>)catalog.Artifacts).Clear()` throws `NotSupportedException` fails on the head and passes with the fix. Add that test (and the same for `ICollection<Artifact>.Add`).

### Suggestions

- **F122 [suggestion] The surface test is too narrow to be the guard the card asks for.** `ArtifactCatalogTests.cs:80-98` looks at `GetMethods(Public|Instance|DeclaredOnly)` minus special names, at public setters, and at the static type of `Artifacts`. 44-mutation run, surface group: caught 6 of 14 real exposures (list above in check 2); **survivors**: public field `List<Artifact> Mutable`; public property `List<Artifact> Mutable => _artifacts`; public property `Dictionary<ArtifactId, Artifact> ById => _byId`; public constructor `ArtifactCatalog(List<Artifact> seed)` that keeps the caller's list; public **static** `Remove(ArtifactCatalog, ArtifactId)`; nested public type with a `Drop(catalog, id)` method; explicit interface implementation `IRemovable.Remove`; extension method that casts `Artifacts`. The test name and the comment ("Adding is the only way to change a catalog") promise more. Fix: list **every** public member (`BindingFlags.Public | Instance | Static`, all member kinds: methods incl. static, constructors, fields, properties incl. indexers, events, nested types, `GetInterfaces()`), and assert the exact allowed set (`ArtifactCatalog()`, `Artifacts`, `Register`, `Find`, `ToText`, no interfaces, no nested types); and assert that no public property or field has a type that is a mutable collection (`List<>`, `Dictionary<,>`, anything assignable to `ICollection<>` whose `IsReadOnly` is false when instantiated), plus the cast test from F121. With the allow-list, any new public member (including a get-only indexer) forces a conscious test edit, which is the point.
- **F123 [suggestion] The comment "sole writer" is now false, and outside code can add to a session's catalog.** `DomainSession.cs:169`: `// Lower always stamps the SyntaxModule sentinel into ArtifactCatalog (sole writer).` Before this PR the property was an `IReadOnlyList` with a private setter, so `Lower` was the only writer. Now `ArtifactCatalog.Register` is public and `session.ArtifactCatalog` returns the live instance. Probe: `session.ArtifactCatalog.Register(new Artifact(new ArtifactDescriptor(ArtifactId.Create(["X"], "t"), "Outside"), null))` after `Lower` succeeds, and `ToText()` becomes `t|X|Outside\nSyntaxModule|module|Lower`; the next `Lower` throws it away. Nothing reads the catalog yet, so no result is wrong today. Choose one: make `Register` `internal` until a producer outside the assembly needs it (A3a), or keep it public and say in the property doc who may call it; and either way fix line 169 (also "sentinel" there versus "placeholder" in the property doc and the card: pick one word).
- **F124 [suggestion] "A value rebuilt whole by each compile" has no test.** Mutation D3 (one `static readonly` catalog shared by all sessions) leaves `ArtifactCatalogTests` and `EmitGoldenTests` green; it is caught only by `SliceCProducerLoopCatalogTests` (5/8) and one reproducibility case, because tests in the same process see each other's artifacts. Add to `SliceC...` or `ArtifactCatalogTests`: (a) two sessions have different `ArtifactCatalog` instances after `Lower`; (b) a second `Lower` on one session gives a new instance and the old one is unchanged; (c) an artifact registered by hand after `Lower` is gone after the next `Lower`. Small, and these are the shared-state mistakes the plan's rule 3 is about.
- **F125 [suggestion] `ToText` order is not pinned to what the comment says.** `ArtifactCatalog.cs:30-33` sorts by `Id.ToString()` (that is `Path#Type`, ordinal) but prints `Type|Path|Producer`. Mutations that survive all 7 tests: comparer `CurrentCulture`, `InvariantCulture`, `OrdinalIgnoreCase`; sort key `Id.Path` only; `Id.Type + Id.Path`; `Producer + Id`. Reason: the one ordering test (`:62-73`) uses `Hotel/Reservation/Confirm#method` and `Hotel/Room#type`, whose order is the same by path, by type, and by case, and every producer is `Lower`. Probe of the real order on mixed ids: `t|Zebra|P ; z|a|P ; t|a/b|P ; t|a_b|P ; t|apple|P` (uppercase first because ordinal, and `a#z` before `a/b#t` because `#` sorts below `/`). Fix: add one test with ids where those orders differ (`Zebra` and `apple`; a type that sorts after while its path sorts before; two producers) and put the expected text in it; one sentence on the sort key in the `ToText` summary ("sorted by `Path#Type`, ordinal"). The goldens cannot help: each has one artifact.

### Nits

- **F126** Null and odd input on the new types is undefined. `Register(null)` throws `ArgumentNullException`, but a null descriptor (`new Artifact(null!, null)`) throws `NullReferenceException` at `ArtifactCatalog.cs:17`; `new ArtifactDescriptor(null!, "p")` gives `ArgumentNullException` from the dictionary; `Find(null)` gives `ArgumentNullException` from `GetValueOrDefault`; a null `Producer` prints as an empty column; a `Producer` with `|` or a newline (`"x|y\nz"`) breaks the "one line per artifact" contract of `ToText` (probe). Mutation F13 (delete `ThrowIfNull(artifact)`) passes all tests. Either validate (`Producer` non-empty, no `|` or newline; `Descriptor` non-null) or state in the summary that the producer is trusted; add `Register(null)` to the tests.
- **F127** Plan card A2a (line 179) is stale: it says the SliceC test is "the only test file that references the catalog", but `EmitGoldenTests.cs` (added by T0) also did and had to change; and `Artifact.cs` is a second new file. Docs only; update when the plan next changes.
- **F128** The new public type name `Artifact` collides with `TUnit.Core.Artifact`, so any test file that uses it needs `using Artifact = Poly.DomainModeling.Compile.Artifact;` (`ArtifactCatalogTests.cs:5`; without it: CS0104). That is the plan's name, so keep it; note it where the next slice's tests will trip on it. Also `DomainSession.Artifacts` (contributors) and `ArtifactCatalog.Artifacts` (compiled artifacts) are two different things with the same name.
