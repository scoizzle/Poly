## Findings (new from F129)

All nits; none blocks.

- **F129 [nit] The order test's name overclaims.** `ArtifactCatalogTests.cs:80`: `ToText_SortsOrdinallyByPathThenType_NotByTypeProducerOrCulture`. The sort key is the string `Path#Type` (`ArtifactCatalog.cs:32`), which equals "path, then type" only when no name character sorts below `#`. `ArtifactId` allows `!` and `"` (and control characters), which do. Probe: ids `a!`/t, `a`/b, `a"x`/t sort as `t|a!|P`, `t|a"x|P`, `b|a|P`, so path `a` (type b) comes after path `a!`. The `ToText` doc is exact ("sorted ordinally by id (`Path#Type`)"); only the test name is loose. Rename to `..._SortsOrdinallyByIdString_...` or add a short comment; no code change.
- **F130 [nit] `Artifacts` allocates a new wrapper on every access.** `ArtifactCatalog.cs:12`: `List<T>.AsReadOnly()` creates a new `ReadOnlyCollection` each call (probe: `ReferenceEquals(c.Artifacts, c.Artifacts)` is false). The view is live (it sees later `Register`s, probe), so correctness is fine; it matters only in a hot loop or if a caller compares or keys on the view. If it ever matters: keep one `ReadOnlyCollection<Artifact>` in a field built with the list. The mill called this a suggestion; I think nit because nothing reads the catalog in a loop yet.
- **F131 [nit] The allow-list test still has small gaps and is a little hard to read.** `ArtifactCatalogTests.cs:113-135`. (a) Constructor shape is not part of the list: replacing the one constructor with a single `public ArtifactCatalog(List<Artifact>? seed = null)` that keeps the caller's list passes all 10 tests (I ran it); a second constructor, as in my earlier mutation, is caught. Fix: list constructor parameters (`GetConstructors()` with parameter types) or assert `GetConstructors().Single().GetParameters()` is empty. (b) Each property appears twice (`Method get_Artifacts` and `Property Artifacts`) because `GetMembers` returns the accessor; filtering `IsSpecialName` for methods would make the list say what it means. (c) `Artifact` / `ArtifactDescriptor` surfaces are not checked; they are records with init-only properties, so there is no setter to catch, and `Payload` is open by design. Inherited members are not a gap: the class is `sealed`.
- **F126** (partial, nit) and **F127** (not closed, nit) stay open as above; **F128** is informational.
