## Findings

Severity: bug = wrong or misleading result; suggestion = fix soon, by hand; nit = polish.

### Bug

- **F132 [bug] `ArtifactDescriptor.References` aliases the caller's list; a forbidden edge can be added after `Register` and nothing notices.** `ArtifactDescriptor.cs:9`: the positional property keeps the `IReadOnlyList<ArtifactId>` it was given (probe: `ReferenceEquals(descriptor.References, callersList)` is true). `Register` validates the references once (`ArtifactCatalog.cs:38-41`); `FindDanglingOrWrongType` (`:66`) reads the same live list later. Probe on the head: type `m` may point at `t` only; `refs = new List<ArtifactId> { R#t }`; register `M#m` with `refs`; `refs.Add(S#x)` (`x` is not an allowed target of `m`); register `R#t` and `S#x`. Result: `Find(M#m).Descriptor.References.Count` is 2 and `FindDanglingOrWrongType()` returns 0 problems, so a forbidden edge sits in the catalog and the checker says all is well. A cast does the same: `((IList<ArtifactId>)descriptor.References).Add(...)` succeeded on the registered descriptor (a `List`-backed one; a collection-expression `[..]` or an array of fixed size does not allow `Add`, which is why the test helper `Make` cannot show it). This is the F121 class from PR 88: a stored collection that aliases outside state. Fix: copy in the descriptor, so the catalog and every reader see one snapshot; for example in `ArtifactDescriptor.cs` an explicit property `public IReadOnlyList<ArtifactId> References { get; } = References is null ? throw new ArgumentNullException(nameof(References)) : References.ToArray().AsReadOnly();`. I applied exactly that in a scratch worktree: the existing 17 catalog tests still pass, and a new test `Register_KeepsItsOwnCopyOfTheReferences` (register through a `List<ArtifactId>`, add an edge to the list afterwards, expect the registered descriptor to still have 1 reference) **fails on the head and passes with the fix** (18/18). The declaration side is already safe (`DeclareType` copies into a `HashSet`; the probe showed that growing the caller's list after `DeclareType` does not widen the allowed targets), but nothing tests it (mutation R8, F134).

### Suggestions

- **F133 [suggestion] Descriptor and artifact equality ignore the content of `References`.** The record compares `References` with `EqualityComparer<IReadOnlyList<ArtifactId>>.Default`, which is reference equality. Probe: two `ArtifactDescriptor`s with the same id, producer and one equal reference built from different lists: `Equals` is `False` and the hash codes differ; with the default empty references they are equal. So `Assert.That(artifact).IsEqualTo(...)` on an artifact with references only passes for the same instance (the existing tests do compare same instances, `ArtifactCatalogTests.cs:36-37, 50, 69`), and the same artifact built twice is not equal to itself. Fix together with F132: give the descriptor value equality over its references (override `Equals` / `GetHashCode` with `References.SequenceEqual`), or normalise references into a small immutable value type that has it. Add one test that two descriptors with equal references are equal and hash alike.
- **F134 [suggestion] Declarations accept names and edges that can never work, and a never-declared target type is not reported as an unknown type.** Probe (all accepted, no error): `DeclareType("")`, `(" ")`, `("a#b")`, `("a/b")`, `"Method"` next to `"method"` (case-distinct, ordinal), `mayPointAt` containing `null`, `""`, `" "` or duplicates, and `DeclareType("w", ["ghost"])` where `ghost` is never declared; registering `W1#w` with a reference to `G#ghost` then succeeds and `FindDanglingOrWrongType()` reports it as `Dangling`. An id's type cannot be empty, blank or contain `#` or `/` (A1), so declared types like these can never have artifacts; they are silent dead state, and a typo in `mayPointAt` (for example `"tpye"`) is reported far from its cause. The card's rule is "an unknown type must not be accepted silently": the artifact's own type is refused, and the dangling report does catch the missing target, so this is a gap in how clearly it speaks, not a breach. Fix: validate declared names with the same rule as `ArtifactId` (non-empty, no whitespace, `/` or `#`; there is one place for it in `ArtifactId.cs:54-59`, currently private), and either report a target type that no one declared as its own kind (`UnknownType`) in the finder or say in its summary that this case reads as `Dangling`. Tests to add: `DeclareType` with null, blank, malformed names; a null element in `mayPointAt`; the `ghost` case; a case-only difference; the caller growing its own `mayPointAt` after `DeclareType` (mutation R8, which stores the caller's collection, survives today).
- **F135 [suggestion] "The producer that defines the type owns that declaration" is a convention, not code.** `DeclareType` takes no producer and records none; `ArtifactDescriptor.Producer` is a free string; the catalog accepts the first declaration of any type from anyone, and `DomainSession.ArtifactCatalog` is the live public instance (A2a F123), so any code can declare a type before the real producer does. The `DeclareType` summary (`ArtifactCatalog.cs:17-19`: "The producer that defines a type calls this once, before registering artifacts of that type") and the card sentence read as a rule; the code only checks "declared once". Fix, either: `DeclareType(string producer, string type, ...)` records the producer and `Register` requires `Descriptor.Producer` to equal it (one dictionary, one comparison, one test); or say plainly in the summary that ownership is by convention until a second producer exists.
- **F136 [suggestion] The finder's result order is registration order, duplicates repeat, and the order test cannot tell registration order from a sorted order.** `ArtifactCatalog.cs:63-75` walks `_artifacts` in registration order and each artifact's references in list order. Probe: the same two artifacts registered `B, A` give `B#m->..., A#m->...`; registered `A, B` give `A` first. `ToText()` sorts for exactly this reason (the text must not depend on registration order); the finder's list does. The same reference listed twice is reported twice. The test `FindDanglingOrWrongType_ListsEveryProblem_InRegistrationOrder_AsAReadOnlyView` names registration order as the contract, but sorting the problems by target (D9) passes it too, because its targets `X, Y, Z` are already sorted, and returning the problems as an array, or de-duplicated, also passes. Path comparison is unpinned: comparing paths case-insensitively (D15) or by prefix (D14) passes all 17. Fix: sort the report by `(From, Target)` with `StringComparer.Ordinal` on their strings, say so in the summary, de-duplicate or document that duplicates repeat; add tests: same catalog registered in both orders gives the same list; a target path that is a prefix of an existing path (`Hotel` vs `Hotel/Room`), and one that differs only by case, are `Dangling`.
- **F137 [suggestion] The surface allow-list covers only `ArtifactCatalog`.** `ArtifactCatalogTests.cs:225-248` reflects `typeof(ArtifactCatalog)`. The PR adds public surface on `ArtifactDescriptor` (`References`, a second constructor), `ArtifactReferenceProblem` and `ArtifactReferenceProblemKind`, and `References` is exactly the member F132 comes from. Mutations that pass today: a public settable `Tag` and a public `List<ArtifactId> Extra` on the descriptor (S8), `References` retyped to `List<ArtifactId>` (S9), a new enum member (S10). Fix: add the same exact-members check for `ArtifactDescriptor` and `ArtifactReferenceProblem` (init-only record members are fine, a plain `set` or a `List` property is not), an assertion that `References` is `IReadOnlyList<ArtifactId>` and that a registered descriptor's `References` cannot be changed through a cast (the F132 test), and pin the enum members (`Dangling`, `WrongType`).

### Nits

- **F138** Null input is handled unevenly. `Register(null)`, `DeclareType(null, ...)` and `DeclareType(.., null)` throw `ArgumentNullException`, but `new ArtifactDescriptor(id, "p", null!)` is accepted and `Register` then throws `NullReferenceException` at `ArtifactCatalog.cs:38`; a null element inside `References` does the same (probe). Deleting the two `ThrowIfNull` lines in `DeclareType` passes all 17 tests (R7). The F132 fix includes the null check for the list; add a test for each throw and for a null element.
- **F139** The plan's A2b Files line names `ArtifactDescriptor.cs` and the catalog file. The PR also changes `DomainSession.cs` (one line, required: `Lower` must declare `SyntaxModule` or its own `Register` is refused) and a SliceC test (one line); the new problem record and enum are in `ArtifactCatalog.cs`, not a new file. Update the card's Files line next time the plan is edited. Also unpinned: what `Lower` declares. Declaring `SyntaxModule` with itself as a target (X2) or an extra type (X3) passes all 47 related tests.
- **F140** `ArtifactDescriptor` has two public constructors (the primary one and `(id, producer)`), which is a second way to build the same value, and the finder scans `_artifacts` for every unresolved reference (`ArtifactCatalog.cs:69`, O(n x m); probe: 3,000 unresolved references over 3,000 artifacts took 117 ms, fine for now). Keep both until A3a gives real references; then drop the short constructor or index the paths. The mill's note that the SliceC test declares a throwaway type on a catalog that `Lower` discards (`SliceCProducerLoopCatalogTests.cs:83`) is true and harmless.
