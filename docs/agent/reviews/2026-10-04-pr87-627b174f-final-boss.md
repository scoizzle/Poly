## Findings

None are bugs. F141 is a suggestion; F142-F148 are nits. Numbering continues from F140 (PR 89).

### F141 [suggestion] The compare's strictness is unpinned: ignoring case and whitespace passes every test
`ParityScenario.cs:60` compares with `!=`. Replacing it with a trimmed, case-insensitive comparison (M9) passes all 29 tests, because no self-test feeds two values that differ only by case or by trailing space and no real row diverges that way. A printer that changed `"Open"` to `"open"` or added a trailing space to a message would be caught today only because the compare happens to be exact. Fix: two more rows in the self-tests (`Differences_WhenValuesDifferOnlyByCase_Reports`, `..._OnlyByTrailingSpace_Reports`) using `Step(message: "a")` vs `Step(message: "A")` and `"a"` vs `"a "`.

### F142 [nit] `Record`'s `created` parameter is the entity model, not the created entity
`ParityScenario.cs:105`: `Record(string step, Func<StepResult> act, Entity? created = null, ...)` is called with `model` (`:89`), and the body reads `created is null ? Current : value` and `created ?? _model!`. In `Create`, the local `created` is the new instance. The same word means opposite things two lines apart, in the one method a hand editor has to understand. Rename the parameter to `createdModel` (or `model`) and give the `subject` line a one-line comment (the existing one above it is enough once the name is right).

### F143 [nit] A scenario cannot pass an empty link list
`ParitySides.cs:72`: `PrintedSide.ToArray` reads `list[0].GetType()` before checking the count. `side.Create("Parent", ("kids", Array.Empty<object>()))` agrees on the simulator and throws `ArgumentOutOfRangeException` on the printed side (reproduced). It fails loudly, so it is not a false agreement, but it is a trap for a hand-written row. Fix: skip empty lists (leave the argument out) or take the element type from the printed navigation.

### F144 [nit] `FindRepoRoot` is copied a fifth time and keeps a check that cannot match
`ParityTests.cs:265-274` repeats the helper that already exists in `SimulateCreateDogfoodTests`, `EmitGoldenTests`, `ProbePlacementGateTests`, `DslCompilerCompileOracleTests`. All test for `Poly.sln`, which does not exist (the repo has `Poly.slnx`); the `docs/CORE.md` branch is what works. Razor F7 suggested reusing one; this PR adds another. Move one copy to `Poly.Tests/TestHelpers` when someone is next in there, and drop `Poly.sln`.

### F145 [nit] The exclusion list is by file name, its name says "invalid", and the floor test name overstates
`ParityTests.cs:232-237`: `InvalidProbes` matches `Path.GetFileName`, so a same-named probe in another folder would be skipped silently, and the comment above `PrintedCSharpCompiles` says a B1 gap "is listed in `InvalidProbes`", which mixes "intentionally invalid" with "known gap owned by B1" (the card's wording). The mismatch test repeats the full path as a string (`:254`). `PrintableProbes_FindsTheSamples` only checks a count of at least 10. Fix: match on the relative path, name the list by what it holds (or add a second `KnownGapProbes` list when the first B1 gap appears), and rename the floor test to say "at_least_ten".

### F146 [nit] Residue of Razor F9: state is compared as text, and a missing printed member reads as null
`ParitySides.cs:52-56, 66-67`: `Read` returns `null` for a member that does not exist on the printed type, the same as a real null, so a null simulator value and a printed property that was not printed agree; values are compared after `ToString()` (a `double` 1 and a `long` 1 agree); a to-one link cannot be expressed in a scenario. Nothing in the current rows depends on any of these. When a row needs one, make `Read` throw for an unknown member (the harness-fault pattern already used for actions) and compare `value?.GetType()` as well.

### F147 [nit] Two paths the helper cannot see: host `TransitionStage`, and a standalone transition or link step
The card's scope names "create, invoke, link, transition". The rows cover a transition that happens inside an action and linking at create time and by create-in-action. `DomainEntityInstance.HostAbi.cs:118` (the simulator's host-driven `TransitionStage`) is not reached by any row (M5b survives; Razor S2). There is no `Link(...)` or `Transition(...)` step. The Done-when is met without them; add them when a C-slice needs a failing-first row there.

### F148 [nit] The state read sits inside the `try` that classifies outcomes, and the unknown-action fault depends on the printed side
`ParityScenario.cs:106-113`: `StateOf` runs inside the same `try` as the step, so an `InvalidOperationException` thrown while reading state would be recorded as a failed step instead of failing the row (read-only observation; I did not find a state read that throws it today). Also, `SimulateSide` reports an unknown action as an ordinary failed step (`Action 'NoSuchAction' not found`, seen in the M6 output); the harness fault is raised only because `PrintedSide.Method` throws. It works because both sides run, but the sides are not symmetric about it. Move the state read out of the `try`, and let `ParitySide.Invoke` check the action exists in `Domain` before dispatching.
