### Suggestions

- **F150 [suggestion, fails the gate] The `DeclareType` summary says a reference to a never-declared target type "can only show up as dangling"; it can also be `WrongType`.** `ArtifactCatalog.cs:19-22`. Probe on the head: `DeclareType("method", ["ghost"])`, `DeclareType("t", [])`, register `G#t`, register `A#method` pointing at `G#ghost`: `FindDanglingOrWrongType()` returns `A#method->G#ghost WrongType`, because an artifact with path `G` exists (type `t`). The test `DeclareType_TargetTypeNeverDeclared_IsAccepted_AndItsReferencesAreDangling` (`ArtifactCatalogTests.cs:336`) only covers the case where path `G` has no artifact, and its name repeats the claim. Fix: say "a reference to it can never resolve (nothing can be registered with an undeclared type), so the finder reports it as dangling, or as wrong type when the path exists with another type", rename the test (for example `..._IsAccepted_AndItsReferencesNeverResolve`) and add the `G#t` case as a second assertion. One sentence, one test.
- **F151 [suggestion] The hand-written `Equals` is pinned only for `References`; `Id` and `Producer` are not.** `ArtifactDescriptor.cs:16-17`. `Descriptor_WithEqualReferences_IsEqualAndHashesAlike` (`ArtifactCatalogTests.cs:282`) varies only the references, so an `Equals` that ignores `Producer` (E6) or `Id` (E7) passes all 60 related tests; two descriptors for different artifacts would then compare equal (and so would `Artifact`s with the same payload). Hash checks only equal-implies-equal, which is the contract, so hash survivors E8, E9, E12 are fine. Fix: two more rows in that test: same references with a different producer, and with a different id, are not equal.
- **F152 [suggestion] The F132 regression test only asserts that `Add` through a cast throws, not that an element cannot be replaced.** `ArtifactCatalogTests.cs:275-277`. If someone drops `.AsReadOnly()` in `CopyOf` (`ArtifactDescriptor.cs:26`), the descriptor keeps a bare `ArtifactId[]`; `((IList<ArtifactId>)registered).Add(...)` still throws `NotSupportedException` (arrays are fixed-size), but `((IList<ArtifactId>)registered)[0] = Hotel#module` succeeds and puts a forbidden edge into a registered artifact, which is F132 again. Mutation E2b (copy to an array) survives all 60 tests. Fix: add `await Assert.That(() => ((IList<ArtifactId>)registered)[0] = ArtifactId.Parse("Hotel#module")).Throws<NotSupportedException>();` next to the `Add` assertion (and a `Clear` for symmetry); the test then also catches E2b.

### Nits

- **F153** Declared type names are compared case-sensitively (consistent with `ArtifactId`, which says so), but no test pins it: `DeclareType("M", [])` next to `DeclareType("m", [])`, or `Register` of an `M` artifact when only `m` is declared. Making the dictionary (R5) or the allowed set (R5b) case-insensitive passes all 60 tests. Add one test with a case-different type.
- **F154** Two declaration behaviours are unpinned: validation of every `mayPointAt` entry (the malformed-name test passes a one-element list, so checking only the first entry, R14, survives) and that a declaration refused for a bad target leaves nothing declared (R11, validating after the add, survives; the head behaves correctly: a refused `DeclareType("m", ["a#b"])` is followed by `Register` of an `m` artifact refused as undeclared, probe). Add a test with a bad entry in the second position and one that registers after a refused declaration.
- **F155** The surface test for `ArtifactDescriptor` and `ArtifactReferenceProblem` pins properties, fields and setters but not methods or constructors, and `Artifact` is not covered: a public method on the descriptor (S11), a settable property on `Artifact` (S9) and an explicit enum value (S13) pass all 60 tests. Fix if you want the same exact-members check as the catalog: reuse its `GetMembers` list for the three record types (init-only and record plumbing excluded), or accept that records only grow properties by deliberate edit.
- **F156** Null handling is uneven at the edges: `new ArtifactDescriptor(null, "p")`, a null `Producer` and `new Artifact(null, ...)` are accepted, and `Register` then throws `NullReferenceException` (probe); a null element in `References` throws `ArgumentException` while a null element in `mayPointAt` throws `FormatException` (from `RequireValid`). Programmer errors, wrong exception type only. Add null checks for `Id` and `Producer` in a validating constructor if you want one rule.
- **F157** Two tiny finder survivors: a target path that merely starts with a registered path (`Hotel/Room` when only `Hotel` exists) matching by "target starts with registered path" instead of exact equality (D14b), and a sort that drops the type from the tie-break (D17, two ids with the same path and different types). The prefix case in the other direction and case differences are tested. Add one row to each existing test.
