## Issues (new)

### Issue F8 -- Severity: suggestion
- **File**: `Poly.Mcp/Tools/DomainTools.cs:151,531`; `Poly/DomainModeling/Evolution/DomainChange.cs:103` (`AddEntityChange`)
- **Description**: The name check is copied into two MCP tools. The C# API (`EvolutionBuilder.AddEntity`, `DomainFactory.Create`) accepts the names and only `Emit` refuses (cleanly), so a bad name survives evolution, analysis and simulate and is found at export.
- **Repro**: `new DomainEvolution(d).Evolve().AddEntity("My Entity").Apply(analysis, session)` → `Succeeded=True`; `session.Emit(...)` → `FormatException: Artifact id name 'My Entity' must be non-empty…`.
- **Suggestion**: validate in `AddEntityChange.ApplyTo` (and `DomainFactory.Create`) with `ArtifactId.IsValidPart`, and let the tools report that mutation error, so there is one seam for MCP, builder and tests.
- **Status**: Open (non-blocking)

### Issue F9 -- Severity: suggestion
- **File**: `Poly/DomainModeling/Compile/DomainSession.cs:186-190`; `Poly/DomainModeling/Analysis/StructuralDomainAnalyzer.cs:65-80`
- **Description**: The `X` / `XStage` entity collision is accepted by analysis and `apply_dsl`, and refused only at Emit/export. The analyzer already rejects the sibling case (a domain enum named `{Entity}Stage`), so the check belongs there (earlier in the feedback ladder).
- **Repro**: DSL `domain Syn` with `X: entity { A: Text required }` and `XStage: entity { B: Text required }`: evolution succeeds; `session.Emit` → `InvalidOperationException: Type 'XStage' belongs to the trees of entities 'X' and 'XStage'.` (master emitted `class XStage` in both `X.cs` and `XStage.cs`).
- **Suggestion**: add the entity-named-`{Other}Stage` rule beside the enum rule in `StructuralDomainAnalyzer`; keep the Emit refusal as the backstop.
- **Status**: Open (non-blocking)

### Issue F10 -- Severity: suggestion
