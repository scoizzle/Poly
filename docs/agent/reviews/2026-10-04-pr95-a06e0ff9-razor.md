## Issues

### Issue F1 -- Severity: bug (needs Scot's decision)
- **File**: `Poly/DomainModeling/Compile/DomainSession.cs:180,187` (`ArtifactId.Create([domain.Name, entity.Name], …)` and `([domain.Name], …)`; rule at `ArtifactId.cs` `RequireValid`)
- **Description**: `Lower` (hence `Emit`) now throws `FormatException` when the domain or an entity name has whitespace, `/` or `#`. Master's `Lower` registered a fixed id, so it never threw. Such names reach `Lower` through MCP `create_domain_session(domainName)` (free string; only empty/whitespace-only is rejected) and `add {kind:"entity", name}`. A domain named `My Domain` exported fine on master and now fails. The PR body discloses the edge ("an API-built domain named `My Domain`") but does not say that the shipped MCP tool reaches it, and no test covers it. The plan (A1, V6) makes the name path the id, so the name must be valid somewhere; today it is checked only at the last moment, deep in Emit, with an id-format message.
- **Repro**: `var (sid,_)=McpSessionStore.Create("My Domain"); EvolveTool.Add(sid,"entity","{\"name\":\"Widget\"}"); OracleTool.ExportDomainToCSharp(sid)` → master `Success=True` (2 files); PR `Success=False`, "Artifact id name 'My Domain' must be non-empty with no whitespace, '/' or '#'."
- **Suggestion** (Scot to choose): (a) recommended: validate the name where it enters (`create_domain_session` and `add entity`, ideally `DomainFactory.Create` / the entity-add change) with the same rule as `ArtifactId.RequireValid`, fail closed with a message that names the offending name, and keep `Lower` throwing as the backstop; add a test for `create_domain_session("My Domain")` and one for an entity name with a space. (b) Keep it as is and record it as accepted (domain-name spaces then become invalid for export; the entity case already produced invalid C# on master). (c) Escape ids from names (not recommended: breaks "id = written name path"). Either way, the decision needs a test.
- **Status**: Open

### Issue F2 -- Severity: bug
- **File**: `Poly/DomainModeling/Compile/DomainSession.cs:158,208-211`
- **Description**: `Emit` calls `Lower` (which assigns the session's `ArtifactCatalog` property) and then re-reads that property to find the trees. Master used a local (`var types = Lower(...)`). With two `Emit` calls on one session for different domain snapshots (MCP `export_domain_to_csharp` takes no lock and runs against the live `state.Domain`), one call can emit the other's trees, or hit the null-forgiving `Find(...)!` and throw `NullReferenceException`.
- **Repro**: one session; threads alternate `session.Emit(domainA, analysisA)` (expect `Alpha.cs,Poly.Types.cs`) and `Emit(domainB, analysisB)` (expect `Beta.cs,Gamma.cs,Poly.Types.cs`), 8 threads x 400 calls. Master: 3188 ok, 0 wrong, 12 `InvalidOperationException`. PR: 1870 ok, **136 wrong files** (110 A-calls got B's files, 26 B-calls got A's), **1194 `NullReferenceException`**. (Same-domain concurrency not tested.)
- **Suggestion**: split `Lower` into a private `LowerToCatalog(domain, analysis)` that returns `(module, catalog)`; `Lower` assigns the property from it, and `Emit` uses the returned local catalog and never reads the property.
- **Status**: Open
