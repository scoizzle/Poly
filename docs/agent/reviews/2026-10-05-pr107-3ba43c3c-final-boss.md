## Hand-editability gate: NO

The code change is small and readable: one `contracts` string plus one suffix. But the doc comment above it now reads:

> Two domains with the same fingerprint have the same types, relationships, entity structures (…), imported contracts (…) and contract binding count. This lets us detect when an evolve operation had zero effective change (e.g. adding a property to a non-existent entity, which silently no-ops in the current evolution layer).

- **The example is false.** Adding a property to a non-existent entity fails loudly: `AddPropertyToEntityChange` → `RequireUpdate`, then "Evolution rolled back: Entity 'Ghost' not found — cannot add property 'X'", with the revision unchanged. This was probed on the tip, and the mill confirms it (`DomainChange.cs:133-137`).
- **"The same types, relationships" is also false as written.** The fingerprint holds only the type count and the navigation count (`T:n|R:n`); names are included only for entities, stages and contracts.

Both sentences existed before this PR. The PR edited this comment and states in its body that "the doc comment now names what is fingerprinted", so the comment is in scope and has to be true.
