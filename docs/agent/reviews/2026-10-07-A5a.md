## Call graph

1. **Producer of the catalog.** `DomainSession.Lower` and `Emit` both call `LowerToCatalog` (`DomainSession.cs:182-191`). That method builds a new catalog, registers source/tree/report artifacts, then `DeclareType("file", mayPointAt: [])`. `Emit` (`DomainSession.cs:261-278`) assigns that catalog and returns only entity `.cs` plus `Poly.Types.cs`. It does not register `file` artifacts.
2. **Producer of host files.** `DslCompiler.OpenCompileSession` (`DslCompiler.cs:285-288`) is the only product `AddArtifactContributor` site: `DbContextArtifactContributor` when a persistence id is loaded, `MinimalApiHostArtifactContributor` when `http` is loaded. Libraries do not register contributors yet (N2).
3. **Consumer.** `CompileCore` (`DslCompiler.cs:174-185`) calls `Emit`, then each `session.Artifacts` contributor and each `_extraArtifacts` contributor, then `ContributedFileFrom` + `Register`, then walks `catalog.Artifacts` and appends type `file` only. `CompileResult.Catalog` is that same catalog object.
4. **Keys.** `ContributedFile.Create` (`IArtifactContributor.cs:27-34`) uses `ArtifactId.Create([domain.Name, fileName], "file")`. `FileName` returns the last segment (`IArtifactContributor.cs:41-46`). `ContributedFileFrom` (`DslCompiler.cs:330-338`) keeps id, payload, and references, and replaces producer with `contributor.GetType().Name`. `Register` (`ArtifactCatalog.cs:43-54`) rejects an undeclared type, a reference whose type is not in `mayPointAt` (empty for `file`), and a duplicate id.
5. **Not-found vs missing contract.** A contributor with nothing to emit returns an empty list (`DbContext` when persistence metadata is absent; Minimal API when both http and storage metadata are absent). A return that is not a `file` artifact or whose payload is not a `string` throws `InvalidOperationException`, which `CompileCore` turns into `Success: false` (`DslCompiler.cs:187-188`). That throw is reachable only from a contributor that violates the contract, not from the four implementers on a valid domain. Analysis errors never reach `Contribute`: `CompileCore` returns at `outcome.Succeeded` (`DslCompiler.cs:156-169`), and `LowerToCatalog` calls `ThrowIfHasErrors` before a catalog exists. Tests force the dirty path (`SliceC_DirtyAnalyze_ContributorsNotCalled`, `Compile_WithArtifactContributor_OnStructuralFailure_EmitsNothing`).
6. **Sibling paths.** There is one catalog constructor in product code. Lower and Emit share it, so the "declare `file` and leave it empty" comment is true on both. `ToText` (`ArtifactCatalog.cs:64-67`) lists registered artifacts only, so an empty declaration does not change `catalog.golden`. `EmitGoldenTests.CompileSample` snapshots `session.Emit`, not the post-contributor catalog. `Crm_DslCompilerHostFiles_MatchGolden` snapshots DslCompiler host files whose names are not emit names. No `*.golden` is in the PR (9 files, +153/−61). Direct `Contribute` calls in tests bypass registration; they still go through `ContributedFile.Create`.
7. **Order and doubles.** File artifacts are registered in contributor order, then appended in catalog order, which is that same order. Emit tuples are not also `file` artifacts, so entity files are not written twice. `GetOrLower` does not call `Lower` (`RuntimeAnalysisCache.cs:98-123`), so the contributor's module lookup does not replace the catalog the compiler just captured.
8. **Invariants checked.** "No references" holds because `mayPointAt` is empty and `Register` rejects anything else. "Producer is the registered type name" holds because `ContributedFileFrom` overwrites the name `Create` stored. "Every `file` artifact is written, entity `.cs` stay tuples" holds by the type filter plus the `Item.cs` assertion (`SliceCProducerLoopCatalogTests.cs:122-123`). The parked pack note that still mentions the old tuple signature (`docs/plans/parked/pack/pack-3c-1-artifact-hook.md`) is historical status text, not a live name this PR renamed.
