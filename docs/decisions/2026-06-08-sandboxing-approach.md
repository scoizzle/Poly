# ADR: VM Sandboxing — Permission Table for CallExternal

**Date:** 2026-06-08  
**Status:** Accepted  

## Context

The VM can call any CLR method via `CallExternal`. A lowered program can invoke `File.Delete`, `Process.Start`, `Environment.Exit`, or any other system API. There is no access control — not even a warning.

For the neurosymbolic platform, untrusted macros may be loaded from external sources or generated by models. These macros execute in the VM via lowering + execution. Without sandboxing, a malicious or buggy macro has full system access.

This is not hypothetical: macro expansion is the core loop of the platform. Macros are composable and may be loaded from libraries. A macro that calls `File.Delete` on expansion is a supply-chain risk.

## Decision

Add a **permission table** checked at `CallExternal` entry. The permission table maps CLR method identities to access levels. Unlisted methods are denied by default.

### Contract

1. **`VmState` gains a `PermissionSet? Permissions` property.** If null, all `CallExternal` calls are allowed (backward compatible, unsafe mode).

2. **`PermissionSet` is a sealed class** containing:
   - `HashSet<string> AllowedMethods` — method identities allowed
   - `HashSet<string> BlockedMethods` — method identities blocked (overrides allowed)
   - `bool AllowAllByDefault` — if true, only blocked methods are denied

3. **Method identity** is the string `"Namespace.TypeName.MethodName"`. Overloads are disambiguated by parameter count (simple) or full signature (configurable).

4. **At `CallExternal` dispatch**, the VM checks:
   - If `Permissions` is null: allow (backward compat)
   - If `AllowAllByDefault`: deny if method is in `BlockedMethods`
   - If not `AllowAllByDefault`: allow only if method is in `AllowedMethods`
   - On deny: throw `InvalidOperationException("Call not permitted: {method}")`

5. **The `Bytecode` carries a `PermissionSet?`** that can be set by the lowering pipeline or the caller. If `Bytecode.Permissions` is set, `VmState.Permissions` is initialized from it at `VmState.Program = program` time.

### Implementation sketch

```csharp
public sealed class PermissionSet {
    public HashSet<string> AllowedMethods { get; } = [];
    public HashSet<string> BlockedMethods { get; } = [];
    public bool AllowAllByDefault { get; init; }

    public bool IsAllowed(string methodIdentity) {
        if (BlockedMethods.Contains(methodIdentity)) return false;
        if (AllowAllByDefault) return true;
        return AllowedMethods.Contains(methodIdentity);
    }
}

// In Vm.cs CallExternal handler:
case OpCode.CallExternal:
    int siteIndex = ReadInt32(code, ref pc);
    if (state.Permissions is not null) {
        var method = prog.CallSites[siteIndex].TargetMethod; // hypothetical metadata
        if (!state.Permissions.IsAllowed(method.Identity))
            throw new InvalidOperationException($"Call not permitted: {method}");
    }
    prog.CallSites[siteIndex](state);
    break;
```

### Default permission sets

- **Unsafe** (default): `Permissions = null` — everything allowed.
- **Safe**: `AllowAllByDefault = false`, allow only `System.Console`, `System.Text.*`, `System.Linq.*`, `System.Collections.*`.
- **Sandbox**: Same as Safe but block file I/O, process, network, reflection, environment.

## Rationale

- Minimal overhead: one `HashSet.Contains` check per CLR call.
- Backward compatible: null permissions = no change.
- Call sites already carry method metadata (the `MethodInfo` used to compile the delegate) — the `TargetMethod` identity can be extracted at compile time and stored alongside the delegate.
- Does not require modification to `CallSiteCompiler` or any existing lowering code.

## Consequences

- `CallSiteDelegate` may need a `MethodIdentity` property for the permission check (or the permission check uses the site index to look up metadata stored in `Bytecode`).
- Permission checks happen at runtime, not at lowering time. This means a valid lowering can produce a program that fails at runtime due to permissions — by design.
- Macros can declare required permissions in their metadata. The expansion pipeline can check at install time.
- Reflection-based calls (`MethodInfo.Invoke`) bypass the permission table unless they also go through `CallExternal`.
