# Emitted expression body: sieve (strided variant)

The body the VM emitter produces for `docs/perf-comparison/sieve_polyvm.cs`, rendered as an
indented expression tree. **This is a diagnostic artifact, not a test input** - it will drift as
the emitter changes, and that is expected. Regenerate with the dumper in
`Poly.Tests/Interpretation/ExpressionBodyDumpTests.cs` (it writes `/tmp/expr-sieve-strided.txt`).

Regenerated 2026-10-23 on `master` @ `7cfdde81`, `CompilationMode.NoDebug`.

Reading notes:

- `_slots` / `_heap` / `_fp` / `_this` are the fixed frame locals; `_regN` are variables;
  `_rN` are ring slots; `_iN` are **Int32** ring slots (IS7c) and `_dN` would be doubles.
- The array buffer lives behind a heap handle in `_r2`: every element access is
  `Convert(_heap.UnsafeGet(Convert(_r2, Int32)), Int64[])` - a call plus a `castclass` - because
  `StridedSetBits` receives the array as an *argument*, so the IS7d cache correctly declines to
  promote it.
- The strided mark loop (`_stride_loop`) contains that deref **twice per iteration**: `|=` lowers to
  `a[i] = a[i] | mask`, and each `a[i]` re-derefs. That is the single largest cost in this program
  and the reason sieve does not benefit from the array cache.
- The only structural difference against the pre-IS7 tree is `_i4:Int32` holding the shift amount
  `6` where the older tree held it in an Int64 slot behind a `Convert` (see the bisect in
  `docs/perf-comparison/README.md`).
