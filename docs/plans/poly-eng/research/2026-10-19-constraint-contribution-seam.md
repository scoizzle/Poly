## Goal

A constraint owns its code generation. It compiles to a **complete AST contribution** — statements at a semantic anchor, supporting methods, declared dependencies — and core places it in the lowered module and threads the dependencies along the closed call set. `unique` is the first real consumer and replaces its lowering and store enforcement arms. The interpreter runs the same body the printer prints.

Three coordinated pieces:

1. **Contribution contract + placement engine** (branch `spike/contributed-methods` — closed PR #233; the branch is slice 1's base).
2. **Storage awareness** (branch `docs/action-dependency-passing` — closed PR #232; evidence only. Units from PR #192 — *not yet built*, see D3).
3. **Lambda bridge** — module `Lambda` nodes become real delegates or `Expression<TDelegate>` at CLR call boundaries.

## Decisions

- **D1 (amended, round 5).** The new ADR "constraints contribute AST at semantic anchors" lands with slice 1's branch. The transport decisions are recorded in this plan; the closed #232 prototype is evidence, not a merge candidate. This plan supersedes #232's absolute "No generator change" non-goal — the route suffix is part of the mechanism.
- **D2 (amended, round 6).** Two anchor kinds, because assign-time unique is not a method-entry guard:
  - *Method anchors* (`OnCreate`, `Named`) resolve to **all** matching lowered methods. `OnCreate` has **two slots**, matching the probe's order (check → construct → record → return, `Program.cs:178-184`): the guard before the first `New`, and a **post-construct record call before return**. The record call records the pending key on `db` (the spike's `Add(code)` shape, or a context method both the generated context and the simulate binding implement). It **must not pass the constructed instance to `DbSet.Add`** — simulate's bound constructor produces a `DomainEntityInstance`, not an EF entity, so a real `DbSet.Add` throws on the VM side slice 5 runs.
  - *Deferred anchors.* `OnCreateIn` is **not** in the contract: create-in paths go through `Create`, and a target type's `Create{Nav}` factory creates the nav's children, not the constrained entity, so a `CreateIn` anchor would guard the wrong values. It returns when source-type resolution is defined. `OnStageEntry` lands with its consumer.
  - *`OnAssign`* splices into the existing fail-before-mutate wrap (`WrapConstrainedAssign`): after the RHS local, after the intrinsic checks, before the assignment. It does not run at method entry, and it checks the assigned value, not a constructor argument.
- **D3 (rewritten, round 2).** Storage today is **one** `StorageModel` and one `{Domain}DbContext`; two persistence libraries cannot even load. Slice 2 consumes that single model; **no `OnlyUnit()` / `AgreedIsUnique` — those are #192 ADR prose and move to slice 6** after #192's bag exists. No private copy of that API in this program.
- **D4 (amended, round 9).** `unique` is vendor-neutral, owned by the persistence library; the product `UniqueConstraintCompiler` lands in 3a. **The no-compiler diagnostic moves to 3b**, in the same change that deletes the store gate: until then a domain without storage still has the gate, so there is no silent skip, and turning the diagnostic on now breaks the storage-agnostic probe fixtures. The diagnostic becomes mandatory only when the old enforcement dies.
- **D5 (amended, round 2).** Board edit cites the **narrowed** row 4 (real `EnsureUnique` only; probes stay unrestored; `StoreBind.cs` is already `StoreJobObjectType` + `TypedNull` — the task file's probe-restoring text is not absorbed). The lambda bridge and multi-unit work get their own rows (bridge under the C# surface track). **Row 4 closes at slice 5**, when print and sim both reject a duplicate and accept a distinct value. `EveryConceptHasTreeTests` oracle retargets to the guard, not the method name `EnsureUnique`.
- **D6 (amended, round 3).** The store unique gate and its callers delete **only once the module guard is VM-executable end to end** (slice 3b, gated on slice 5 parity). The delete set is: `DomainInstanceStore.cs:299/:325` (`TryAdd`/`EnsureUnique`), the `SetProperty` path, the host job and its callers (`DomainEntityInstance.HostAbi.cs:35`, `DomainEntityInstance.Runtime.cs:142` — the build forces these, but the set names them so 3b is not a hunt), and the `DomainEntityInstance.cs:937` catch that converts the throw into `Failure`. Deleting earlier leaves simulate with no enforcement.
- **D7′ (D7 withdrawn; amended round 7).** EF lives in the generated `{Domain}DbContext`'s implementation of the storage port (D8). The module names the port, not the context; the port's `Exists` is visible-in-unit-of-work (pending record OR database), and `Record` adds the pending key. The module still never holds an EF predicate; the D9 flip remains the option that moves a predicate into the module.
- **D8 (decided round 7: option (a), in-process read-only storage port).** The `db` dependency is typed as an in-process port in `Poly.DomainModeling.Runtime`:
  - `bool Exists(string entity, string property, string value)` — true when the value is visible in this unit of work: a pending record or the database. This is the single check the guard calls; it preserves D11-B's "pending OR database" rule without a second read.
  - `void Record(string entity, string property, string value)` — the post-construct pending-key record.
  - No writes and no `SaveChanges`; the host's `Add`/`SaveChanges` stay host-side.
  The generated `{Domain}DbContext` implements the port per unit (EF queries for `Exists`); the simulate host supplies an in-memory implementation. This makes the module provider-agnostic by construction, keeps the type in-process for the VM (`ClrTypeReference`), and leaves multi-unit as host binding (slice 6). Options (b) Roslyn-compile-the-host and (c) name-resolved VM binding are rejected: they couple simulate to a generated assembly or a bespoke type provider for no capability the port lacks.
  Consequences: `ConstraintCompileRequest` carries the entity's single `StorageModel` mapping (D3); a constraint needing storage with no mapping fails closed. Slice 2 implements the port, the request fact, the catalog reads, and the route/POST/seed suffix; slice 3a registers the product compiler against the port.
- **D9.** Predicate placement: context partial for slice 3; the lambda bridge enables a later flip into the module with no contract change — only the supporting method's body source moves.
- **D10 (rewritten, round 8 — after the mode analysis; confirmed by Scot 2026-10-19):** the split is by **parameter kind**, not by compilation mode:
  - **Trigger:** the argument node is a `Lambda` and the resolved parameter CLR type is a delegate `D` or `Expression<D>`.
  - **Delegate `D` → VM re-entry adapter, in every mode.** The call argument is a delegate that captures the existing function-table body, its closure handle, the state, and the table. Invocation re-enters the VM through the same frame protocol as `InvokeHeapClosure`. Captures are the live `long[1]` cells (C# reference semantics), and the body supports the full module language — no second pure lowering for delegates. Fails closed after execution, off-thread, and for `Task`/`Task<T>` returns.
  - **`Expression<D>` → pure quoted tree, in every mode.** Captures spill to typed locals (a documented snapshot); the body passes the AST allow-list; the tree is what a query provider translates.
  - **`CompilationMode` stays instrumentation-only.** `Normal` and `NoDebug` must run the same lowering; the mode only controls `DebugHook`/PC/loop guards.
  - **Void (`Action`) bodies:** a block body is statement-form (its trailing value is discarded); a non-block value-form body against a void `D` throws; a non-void `D` with a statement body throws. No value discard for expression bodies.
  - **Debug scope:** statement step-into works today for block-bodied lambdas invoked synchronously. Expression-bodied bodies bypass the hook, per-body locals are root-only, and `SuspendNode` cannot cross a CLR frame — these are L2, not claimed here. No breakpoints inside bridged bodies.
  - **Non-goals v1:** async delegate returns, `this` capture, nested lambdas inside a bridged body, generic-method closing, and escaped delegates beyond the dynamic extent of the execution (enforced by the `IsExecuting`/thread guard).
- **D11 (amended, round 7 — who checks and who tracks).** Contract **B**, the minimal consistent rule, expressed through the D8 port:
  - The guard calls the port's `Exists(entity, property, value)` — **pending-key record OR database**, one check. The module's post-construct record call (D2) calls `Record(entity, property, value)` with the **key**, never the instance.
  - Both host `Add`s **stay** (the POST `db.Set.Add` at `MinimalApiGenerator.cs:457-462` and `SeedAsync`'s `db.Add` at `:1072-1073`). They persist; they are not a unique check. `SaveChanges` stays host-side.
  - A nested second create fails **before `SaveChanges`** because the first create's key is already in the pending record; print and sim both go through the same port surface (no instance-type asymmetry).
  - *Contract A* — the probe's shape: the module calls a generated `RecordCreated(instance)` that the printed context implements as `DbSet.Add` (so `Local` and `SaveChanges` see it), both host `Add`s delete, and `ExistsWith` stays `Local.Any || Set.Any` — is recorded as the alternative, superseded by the port. **B is the decision.**
  - The earlier "read-only / no writable storage surface" non-goal is withdrawn and replaced by: writes through the dependency are exactly the pending-key record; `Add` and `SaveChanges` stay host-side.
