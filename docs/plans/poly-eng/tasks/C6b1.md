## Scope
Cardinality is enforced nowhere at link time. `DomainInstanceStore.Link` (`Poly/DomainModeling/Runtime/DomainInstanceStore.cs:355-365`) only checks both instances are registered and de-dupes; the printed `Create{R}` simply sets the singular nav (`Poly/DomainModeling/Lowering/DomainToCSharpExporter.Notify.cs:238-242`). The DSL link path is `create in Rel` -> `this.CreateIn(rel, …)` (`Poly/DomainModeling/Lowering/EffectLoweringPass.cs:908-918`); the parity harness links through `_store.Link` (`Poly.Tests/TestHelpers/ParitySides.cs:24-26`).
Decision 11: the relationship owns link effects. A relationship that is singular at its source (`OneToOne`, `ManyToOne`; i.e. `Cardinality is not OneToMany/ManyToMany`) permits at most one outbound link per source. Enforce that at the two entries the card names: the shared lowered `create in` tree (both simulation and print run it) and `DomainInstanceStore.Link` (covers MCP `link_instances`, `RuntimeTool.cs:337-349`). `OneToMany`/`ManyToMany` keep unbounded targets. Decision 10 (C6a, merged #144) already made links explicit; this adds the capacity bound.
