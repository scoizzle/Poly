# TASK C6b2 - Self-referencing collection slot is a list, not `this`
Status: planned. Branch slice/c6b2-plan. Lane B. Review 2. Implement mill: Grok (review on OpenCode).
## Scope
Grug on PR 144 (R3 follow-up) and archived probe `docs/plans/archive/probes-2026-08/findings/round4/agent-c.md:44-70` (F1): a self-referencing navigation (target type == owning entity) is flagged `IsBackReference` in `EntityStructureAnalyzer.ComputeConstructorParameterOrder` (`Poly/DomainModeling/Analysis/EntityStructureAnalyzer.cs:121-127`), and a `many` one is *also* `IsCollection`. Both emit sites test `IsBackReference` before `IsCollection`, so they pass `this` where the ctor wants `IEnumerable<T>`. Verified on master `931b1461` by exporting `Node { Name: Text required; parent: Node; children: many Node }`: `Node.Create(name, this, this)` appears in `BindCreate`, `BindProbeCreate`, `CreateParent`, `CreateChildren` — invalid C# (`CS1503`, `Node` is not `IEnumerable<Node>`). `BuildTargetCreateArgs` (`StoreBind.cs:216-241`) is the site Grug named; `AddCreateNavMethod` (`Notify.cs:92-151`, also reached by `AddCreateSingularNavMethod:84-90`) is the identical twin and must change too or the domain still will not compile. Fix both by handling a collection slot before a back-reference slot; a singular self-rel back-ref keeps `this` (source == target) / `TypedNull` otherwise.
