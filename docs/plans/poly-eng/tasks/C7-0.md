## Scope
Card C7-0 asks for a small index over the catalog: "method by name on a tree, tree by name, navigation by name," index unit tests only, no consumer changed, and it must not duplicate existing cache logic. On master the trees live in an `ArtifactCatalog` (`Poly/DomainModeling/Compile/ArtifactCatalog.cs:8`, `Find` `:58`), registered by `DomainSession.RegisterTrees` (`Poly/DomainModeling/Compile/DomainSession.cs:233-266`) as one `entity` tree per entity (id `domain/Entity#entity`, payload `IReadOnlyList<TypeDefinitionNode>`, `:252-257`) plus one `scaffolding` tree (`domain#scaffolding`, `:260-265`; cast helper `TypesOf` `:379-380`). The name lookups consumers use today are hand-written: `RuntimeAnalysisCache.TryGetModuleMethod` scans the cached module by type then method name (`Poly/DomainModeling/Analysis/RuntimeAnalysisCache.cs:126-150`; `TryGetEntryMethod` `:152`, `TryGetExitMethod` `:160`), and relationship members are matched by PascalCase name in `DomainEntityInstance.Runtime.cs:363-372` and `:409-419`. C7-0 replaces none of those yet: it adds a read-only `CatalogIndex` over one catalog that answers the three lookups. It caches nothing — no analysis, no module, no bodies — so it cannot duplicate `RuntimeAnalysisCache`.

`Navigation` matches the lowered member name as written in the tree (PascalCase of the relationship name, e.g. `Fines`), the same name `DomainEntityInstance.Runtime.cs:367` matches; an unknown name returns `null`. If an entity and the domain share a name, `Tree` returns the entity tree (documented on the method).
