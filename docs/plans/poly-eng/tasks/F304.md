# TASK F304 — DSL printer quotes contract source and version (quoting follows the parser's identifier rule)

Status: PR 116 at ab2902d7, in review (Final Boss, Review 1).

Lane B. Review 1: Final Boss on the mill opposite the implementer. From the PR 99 review cards.

## Scope
The DSL printer writes a contract's source and version unquoted (for example source `default`, version `1`), so applying the printed DSL again fails. `PrintContract` already runs both values through `NeedsQuotes` (`DomainDslPrinter.cs`); the bug is `NeedsQuotes` itself, which checks characters only, so a keyword (`default`) or a leading digit (`1`) stays bare while `PolyDslParser.ParseContract` accepts only a string literal or an identifier. Fix: the printer's quoting decision follows the parser's identifier rule (one shared rule, no second copy).

## Done when
Round-trip test: a contract with source `default` and version `1` prints, re-applies, and prints the same text. Smallest readable change; shape matrix + self-review sweep; hand-edit gate YES.
