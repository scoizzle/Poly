## The edit
In both `expr-primary` and `expr-primary-no-not`, after `quant-where` and `count-bare`:

```text
.Pattern("sum-prop", priority: 2)
    .Predicate(IsSumToken, "quant")
    .Value(DslTokenKind.Identifier, "rel")
    .Predicate(IsPathHopIdent, "prop")
    .Commit()
```

`IsSumToken` is an identifier whose text is `sum`, same shape as `IsCountToken`. Adding `sum` to `IsQuantifierKeyword` keeps `sum` out of `path`. The property predicate is `IsPathHopIdent`, so `where` is not a property name and `quant-where` still wins on `sum lines where …`.

`FoldPrimary`: `"sum-prop" => DomainExpression.Sum(CaptureText(match, "rel"), CaptureText(match, "prop"))`.

`FoldQuantWhere` arm: `"sum" => throw _c.Error("sum does not take where; write sum Rel Prop")`.

`SumExpr` is `sealed record SumExpr(string RelationshipName, string PropertyName) : DomainExpression` with `Children` empty. Do not overload `CountExpr`.
