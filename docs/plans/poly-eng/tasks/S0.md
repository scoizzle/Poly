## Scope
- On master `13948930` the core analysis pipeline is a hard-coded lazy list: `DomainModelAnalyzer.BuildPipeline` (`Poly/DomainModeling/Analysis/DomainModelAnalyzer.cs:18-29`) is called by `DomainSession.Analyzer` (`Poly/DomainModeling/Compile/DomainSession.cs:80-84`). There is no stage tag anywhere.
- `SessionBuilder.Load` (`Poly/DomainModeling/Compile/SessionBuilder.cs:34-45`) registers a library with no stage, and `SessionBuilder.Build` (`:94-112`) hands the session only the extra analyzers.
- Core is not a `uses` id: `ExtensionCatalog.Core` lists `temporal`, `storage`, `persistence` only (`Poly/DomainModeling/Compile/ExtensionCatalog.cs:29-32`); the parser and evolution resolve ids against that catalog (`Poly/DomainModeling/Language/PolyDslParser.cs:155-157`, `Poly/DomainModeling/Evolution/DomainChange.cs:686-690`).
- S0 keeps core out of the catalog and makes it an implicit library loaded at `PipelineStage.Load`; its 21 passes enter through `SessionBuilder.Load` instead of a private factory. `DomainSession.Extensions` stays authored ids only.

## Done when
- `CoreLibraryTests.Core_AnalyzerPipelineRequiresCoreLibrary` passes. The test builds `SessionBuilder.CreateEmpty().Load(new MarkerLibrary()).Build()` and asserts `session.Analyze(domain)` throws `InvalidOperationException` with a message containing `core`. Write this test first and run it red: on master it compiles and fails because `Analyze` succeeds. `Core_ContributesItsPassesAtLoad` asserts `DomainSession.ForExtensions([]).Contributions` starts with `(PipelineStage.Load, "core")` and `Analyzers[0].PassName == StructuralDomainAnalyzer.Id`.
- New `Poly/DomainModeling/Compile/PipelineStage.cs`: `public enum PipelineStage { Parse, Load, Resolve, Evolve, Analyze, Lower, Produce, Consume }`, in that order.
- New `Poly/DomainModeling/Compile/StageContribution.cs`: `public sealed record StageContribution(PipelineStage Stage, string LibraryId);`.
- New `Poly/DomainModeling/Compile/CoreLibrary.cs`: `public sealed class CoreLibrary : IDomainLibrary`, `public const string CoreId = "core"`, `public string Id => CoreId`, and `Register(SessionBuilder builder)` adds each pass from `DomainModelAnalyzer.CorePasses(builder.Meaning, builder.ExpressionForms)` with `builder.AddAnalyzer(pass)`.
- `SessionBuilder`: add `_contributions` and `public IReadOnlyList<StageContribution> Contributions`; `Load` appends `new StageContribution(PipelineStage.Load, library.Id)`; add `public SessionBuilder LoadCore()` that registers `new CoreLibrary()`, appends `(PipelineStage.Load, CoreLibrary.CoreId)`, and does **not** add `"core"` to `_loadedIds`. It adds `CoreId` to the duplicate-id set, so a second `LoadCore` or a `Load(new CoreLibrary())` throws like any duplicate id.
- `DomainSession`: add `public IReadOnlyList<StageContribution> Contributions` (set in `Build` and carried by `WithDomain`); rename `ExtraAnalyzers` to `Analyzers` (it now holds core plus library passes); build the pipeline as `_analyzer ??= BuildAnalyzer()` and throw `InvalidOperationException("The analyzer pipeline requires the core library loaded at Load.")` when `Contributions` has no `(PipelineStage.Load, CoreLibrary.CoreId)` entry.
- `DomainModelAnalyzer`: delete `BuildPipeline`; add `internal static IReadOnlyList<INodeAnalyzer> CorePasses(ExpressionMeaning? meaning = null, ExpressionFormRegistry? forms = null)` holding the same 21 passes in the same order; `UseDomainModelAnalysisPipeline` loops it. No second copy of the list.
- `DomainSession.ForExtensions` and `ForAuthoringSource` call `LoadCore()` before resolving authored ids. `ExtensionCatalog` is not edited, so `uses core` stays unknown.
- `DomainSessionTests.Analyze_LibraryPassClashesWithCorePassName_Throws` is renamed `Load_LibraryPassClashesWithCorePassName_Throws` and asserts `DomainSession.Open(domain, catalog)` throws with `DomainCatalogPass.Id`; the clash now fails at Load.
