## Findings

### F1 — `Today` lowers inconsistently: bare assign → local `DateTime.Today`; offsets and policy reads → UTC `DateTime.UtcNow` (🟠)
- Signal: divergence (+ guide drift). Slice: temporal lowering / Sim-Export parity.
- Repro: `docs/missions/evolve-2026-10-13/library.poly` (v2/v3). VM run at ~23:30 CDT (UTC-5, so UTC date = next day): `CheckOut` sets `DueDate = Today + 14 Days` → **10/28/2026** (Oct 14 UTC + 14); `Return` sets `ReturnedOn = Today` → **10/13/2026** (local). Same `Today` token, two dates, minutes apart, same session.
- Expected: guide §8 — `Today` lowers to `DateOnly.FromDateTime(DateTime.UtcNow)` ("Policy/VM reads of Now/Today lower to DateTime.UtcNow / DateOnly.FromDateTime(DateTime.UtcNow)").
- Actual: export emits `DateOnly.FromDateTime(DateTime.Today)` (local) for bare `assign X to Today` (library-export-v2/Loan.cs:46,52), but `DateOnly.FromDateTime(DateTime.UtcNow)` for `Today + 14 Days` (Patron.cs:74,79) and for policy comparisons (Patron.cs:117). VM mirrors the export, so the divergence is in the shared lowering.
- Proposed fix: pick one clock for `Today` (guide says UTC): lower bare `Today` the same way as offsets/policies, or introduce a separate local-date token. One lowering site should own every `Today` fold.

### F2 — Same action name on two stages → duplicate Minimal API route → AmbiguousMatchException (HTTP 500) (🔴)
- Signal: compile-fail (ASP0022 warnings) + runtime 500. Slice: Minimal API emitter.
- Repro: `library.poly` declares `Return` in both `Active` and `Overdue` (normal domain shape). Export `--mode all` + host build (aspnet analyzers): `Program.cs(256,13): warning ASP0022: Route '/api/patrons/{email}/loans/{id}/return' conflicts with another handler route`. `POST /api/patrons/{email}/loans/{id}/return` → **HTTP 500**, server log: `AmbiguousMatchException: The request matched multiple endpoints.` demo.http also lists the action twice.
- Expected: one endpoint for the action (or per-stage routing); requests succeed; 0 warnings on the emitted host.
- Actual: two identical `MapPost` registrations (Program.cs:256-290 and 328-362); any request to the action 500s. The exported API is unusable for any action authored on ≥2 stages.
- Proposed fix: dedupe endpoints per action name (merge stage-gated handlers into one registration), or make per-stage bodies fold into a single handler. Emit the `.http` entry once.

### F3 — Generated `GET /api/patrons/{email}/loans/{id}` ignores the `{id}` route parameter (🔴)
- Signal: silent gap. Slice: Minimal API emitter.
- Repro: host on `library.poly`: create patron, 2 checkouts, then `GET /api/patrons/alice@example.com/loans/999` → HTTP 200 with the **first** loan, not 404.
- Expected: fetch the loan with that id (or 404 when absent).
- Actual: `Program.cs:94`: `var child = parent.Loans.FirstOrDefault();` — `{id}` is never used; returns an arbitrary loan regardless of id, 404 only when the collection is empty.
- Proposed fix: filter by the id (`FirstOrDefault(l => l.Id == id)`) or 404.

### F10 — Only one `unique` per entity is projected to storage (as PK); additional uniques vanish silently (🔴)

### F11 — Entity named `Program` breaks `uses http` compilation; `Program.cs` filename collides in db mode (🔴)

- Proposed fix: make artifact keys collision-proof (per-artifact prefixes for generator-owned files, or rename the entity file), and fail-closed with a named-entity diagnostic instead of an artifact-registry exception.

### F14 — Fan-out fail-fast leaves partial state; subscription side-effects fire on that partial state (🟠)
- Signal: divergence from user expectation / documented-gap sharpened. Slice: fan-out invoke semantics.
- Repro: `docs/missions/evolve-2026-10-13/smarthome.poly` v2. Scene with Light(60W), Fan(200W), Heater(3000W); `TurnOn` has `require not TooHot` (`Power > 2500`). The caller sees a failure but the domain shows a half-activated scene with no way to undo atomically.
- Expected: guide §6 documents fail-fast ("the first record whose invoke fails fails the whole `for`") and notes "Rollback of already-invoked records is a documented gap". The subscription cross-fire on partial state is not called out.

### F15 — `Number` is integral (`long`) everywhere; fractional values silently truncate (🔴)
- Signal: silent gap / data corruption. Slice: type system + VM store.
- Repro: `docs/missions/evolve-2026-10-13/billing.poly`. `create_instance` Meter with `Rate: 0.25` → stored as `0`. `AddReading(usage: 200)` + `BillAll` → `Amount = Usage * rate` = **0** for every reading. Export: `public long Rate`, `public long Amount` (billing-export/Meter.cs:20-23, Reading.cs:23).

- Actual: fractional create values are accepted and silently truncated to integers; every computation downstream inherits the corruption. The guide's Money example (`Amount: Number`) never states Number is integral-only.
- Proposed fix: reject fractional input at the tool boundary (fail closed), or introduce a Decimal type; document integral-only if it stays.

### F16 — VM crashes (IndexOutOfRange) on `if` + `create in` when the branch is skipped and a Number property ≥ 256 (🔴)
- Signal: compile-fail of the runtime path (unhandled VM exception) / VM-export divergence. Slice: Interpreter.

- Proposed fix: find the byte-truncating index computation in the VM's branch/effect planning; add a regression test with values on both sides of 256.

### F25 — Date arithmetic on an unset Date property → raw NRE (🟠)
- Signal: fail-loud-but-sharp (VM crash-class error). Slice: Interpreter error handling.
- Repro: `saas.poly` v1: `Activate { assign Expiry to Expiry + 30 Days }` with `Expiry` never set → `Action execution failed: Object reference not set to an instance of an object.` No transition occurs (good) but the error is an unhandled-exception message, and the export would NRE the same way (`this.Expiry.AddDays(30)`).
- Expected: a domain-level failure naming the unset property ("'Expiry' is not set").
- Proposed fix: null-check temporal operands in both VM and export and return a named domain failure.
